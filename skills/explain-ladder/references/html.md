# html — 조작해 보며 이해하는 단일 파일

변수나 시나리오를 바꿔 봐야 이해되는 것에 쓴다. 파라미터 효과, 여러 실패 경로, 알고리즘 단계.

## 1. 파일

- **단일 HTML 파일.** CSS·JS 는 인라인. 외부 스크립트, CDN, 웹폰트, `fetch` 등 네트워크 호출을 넣지 않는다.
- 저장 위치: 사용자가 지정하지 않으면 작업 디렉터리의 `explain/<주제-slug>.html`.
- 만든 뒤 경로를 알려 주고, macOS 면 `open <path>` 로 열 수 있다고 안내한다.

## 2. 구조 (위에서 아래로)

1. **제목**
2. **3문장 요약** — 조작하지 않는 사람도 핵심을 얻어야 한다. 정확히 세 문장.
3. **컨트롤 + 시각 영역** — 핵심 개념을 조작하는 컨트롤 최소 1개.
4. **읽는 법** — 무엇을 바꿔 보고 무엇을 관찰하면 되는지 2~3줄.

## 3. 컨트롤

| 이해할 것 | 컨트롤 |
|---|---|
| 연속 파라미터의 효과 (learning rate, 임계값) | 슬라이더 `<input type="range">` + 현재 값 표시 |
| 이산 시나리오 비교 (실패 경로, 입력 종류) | 라디오 버튼 / 탭 |
| 알고리즘 진행 | 단계 재생: ◀ 이전 · ▶ 다음 · ⏯ 자동 재생, 현재 단계 번호 표시 |

- 조작 **즉시** 시각 결과가 바뀐다. "적용" 버튼을 두지 않는다. `input` 이벤트를 쓴다.
- 컨트롤 라벨에 실제 이름을 쓴다 (`lr`, `max_retries`).
- 키보드로도 조작 가능해야 한다 (기본 폼 요소를 쓰면 된다).

## 4. 시각 영역

- 그래프는 인라인 SVG 나 `<canvas>` 로 직접 그린다. 차트 라이브러리를 불러오지 않는다.
- 축에는 이름과 단위를 쓴다.
- `dataviz` 스킬이 있으면 차트 색·축·범례는 그 규칙을 따른다.
- 시뮬레이션 영역에는 **"예시용"** 라벨을 눈에 띄게 붙인다.
  예: `<span class="badge">예시용 — 2차 손실 함수 위의 경사하강 시뮬레이션, 실측 아님</span>`
- 시뮬레이션 모델은 단순하게 두고, 무엇을 단순화했는지 한 줄로 쓴다.

## 5. 애니메이션

- 이해를 돕는 곳에만 쓴다: 단계 이동, 값 변화에 따른 궤적. 장식 애니메이션을 넣지 않는다.
- `prefers-reduced-motion: reduce` 면 애니메이션을 끈다.

## 6. 라이트 / 다크 모드

CSS 변수로 색을 정의하고 `prefers-color-scheme` 으로 전환한다.

```css
:root { --bg:#ffffff; --fg:#1a1a1a; --muted:#666; --accent:#2563eb; --warn:#d97706; --grid:#e5e5e5; }
@media (prefers-color-scheme: dark) {
  :root { --bg:#111418; --fg:#e8e8e8; --muted:#9aa0a6; --accent:#60a5fa; --warn:#fbbf24; --grid:#2a2f36; }
}
```

SVG·canvas 도 이 변수를 읽어 그린다 (canvas 는 `getComputedStyle` 로 값을 읽고, `matchMedia` 변경 시 다시 그린다).

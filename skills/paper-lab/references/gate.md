# gate — 구현 가치 판정

코드 이전에 30분. 입력은 논문 PDF 또는 `study/note.md` 하나다.

**판정 대상은 재현 가능성이 아니다.** "이 논문을 재현할 수 있나" 로 물으면 거의 모든
논문이 탈락하고 게이트가 무용해진다. 판정 대상은 하나다.

> **내 예산 안에서 답이 분기할 수 있는 질문이 이 논문에 남아 있는가.**

남아 있지 않으면 — 결과가 자명하거나 확인 수단이 예산 밖이면 — 구현은 코드 연습에
해당한다. 그 판정 자체가 이 모드의 산출이며, 대부분의 논문에서 정답은 `읽기만` 이다.

---

## 1. 가능성 질문 다섯

하나라도 빨강이면 착수하지 못한다. 논문의 어디를 보는지까지 고정한다.

### Q1. 기여의 경계

**어디를 보나.** 방법 절의 구조 그림, 그리고 "we modify" · "we replace" · "built on" 이
걸리는 문장.

**초록.** 변경 대상이 한 함수·한 모듈·한 프롬프트 블록으로 지시된다.
**노랑.** 변경이 두세 지점에 분산되지만 각각 경계가 분명하다.
**빨강.** 변경 대상이 시스템 전체이거나, 무엇을 바꿨는지 방법 절에서 특정되지 않는다.

기여의 경계가 흐린 논문은 구현이 아니라 재작성이 된다.

### Q2. 공개 시스템에 대한 델타 여부

**어디를 보나.** 베이스라인 절, `Implementation Details`, 그리고 프롬프트·설정을 물려받았다고
기재한 부록.

**초록.** 공개된 기존 시스템 위의 변경이고 그 시스템의 코드가 접근된다. 기준선을 구축하지
않아도 된다.
**노랑.** 기존 시스템의 코드는 있으나 논문이 그것을 수정한 범위를 명시하지 않는다.
**빨강.** 기준선까지 처음부터 구축해야 한다.

이 질문이 예산의 대부분을 결정한다. 델타면 기여만 구현하고, 아니면 논문 두 편을 구현하는
일이 된다.

### Q3. 데이터·환경 접근성 — 치명

**어디를 보나.** 데이터셋 절, 각주의 URL, `Reproducibility` 문단.

**초록.** 공개 데이터셋이고 내려받을 수 있다.
**노랑.** 공개이나 무겁다(대용량 덤프, rate limit 이 있는 공개 endpoint). 부분집합으로
축소 가능한지 확인한다.
**빨강.** 비공개 데이터, 사내 KB, 소실된 덤프, 접근에 심사가 필요한 코퍼스.

**치명 빨강이다.** 다른 무엇으로도 보완되지 않는다.

### Q4. 평가의 결정성과 비용 — 치명

**어디를 보나.** 지표 정의 문장, 평가 스크립트 언급, `human evaluation` 유무.

**초록.** 실행 기반·규칙 기반 지표이고 채점기가 공개되어 있다.
**노랑.** 표준 지표이나 구현이 여러 개다(BLEU, ROUGE, F1 의 정규화 규칙). 구현 차이가
격차의 최대 원인이 되므로 `gap` 의 1순위 용의자로 미리 기재한다.
**빨강.** 비공개 채점기, 사람 평가, 명세 없는 LLM judge.

**치명 빨강이다.** 채점을 재현할 수 없으면 무엇을 비교해도 비교가 아니다.

### Q5. 실행의 결정성

**어디를 보나.** `Implementation Details` 의 온도·시드·반복 횟수, 표 캡션의 분산 표기.

**초록.** 온도 0 또는 시드 고정이 명시되고 분산이 보고된다.
**노랑.** 온도가 명시되나 분산 미보고. 3시드로 직접 잰다.
**빨강.** 본문과 부록의 설정이 어긋나거나 확률적 호출이 매 턴 발생하는데 반복 횟수가
미보고다. 비용이 반복 횟수만큼 곱해진다.

빨강이어도 착수는 가능하다. 대신 예산을 3배로 잡거나 주장의 해상도를 낮춘다.

## 2. 가치 질문 넷

가능해도 여기서 걸리면 구현하지 않는다.

### Q6. 논문의 절제 유무

**초록.** 기여 요소마다 절제가 있고 표로 보고된다. 5칸의 합격 조건이 이미 논문에 있다.
**노랑.** 절제가 일부 요소만 포함한다. 빠진 요소가 `run` 의 추가 절제 후보가 된다.
**빨강.** 절제가 없고, 무엇을 제거해야 기여가 사라지는지 방법 절에서도 도출되지 않는다.

절제가 없는 논문은 성공의 정의를 세울 수 없다.

### Q7. 축소 후 주장의 존속

**어디를 보나.** 모델 크기별·데이터 규모별 결과, 그리고 같은 방법을 다른 모델로 돌린 표.

**초록.** 작은 설정에서도 이득이 보고되거나, 이득의 기제가 규모와 무관하다.
**노랑.** 축소 결과가 보고되지 않아 모른다. 이 자체를 답할 질문으로 삼을 수 있다.
**빨강.** 모델·데이터를 줄이면 이득이 소멸한다고 논문 자신이 보인다.

빨강이면 `읽기만` 으로 가거나, 소멸 여부 자체를 질문으로 교체한다.

### Q8. 구현으로만 답할 공백

**어디를 보나.** `study/note.md` 의 `읽으며 든 의문` 절. 노트가 없으면 절제표에서 빠진
요소, 한 설정에서만 제시된 분해, 분모가 작은 개선.

**초록.** 논문이 측정하지 않았고 내 예산에서 측정 가능한 항목이 하나 이상이다.
**빨강.** 논문이 이미 전부 측정하였다. 구현의 산출이 논문의 재확인에 그친다.

### Q9. 내 업무에서의 사용 계획

**초록.** 이 방법을 내 데이터·내 파이프라인에 적용할 계획이 있다.
**빨강.** 호기심뿐이다. `paper-tutor` 의 `read` 로 충분하다.

## 3. 질문 교체

치명 빨강(Q3·Q4)이 아닌 빨강은 대개 질문 교체로 통과한다. 교체는 세 방향이다.

| 원래 질문 | 교체 후 | 잃는 것 |
|---|---|---|
| 논문 표의 절대 수치를 일치시킨다 | 절제가 같은 방향·같은 순서를 보이나 | 다른 논문과의 비교 가능성 |
| 전체 설정 N개를 돌린다 | 가장 작은 설정 하나를 돌린다 | 설정 간 일관성 주장 |
| 논문과 같은 모델로 돌린다 | 작은 모델로 돌려 이득의 존속을 본다 | 논문 수치와의 대조 |

세 번째 교체에는 경고가 붙는다. **모델을 내리면 절제의 방향까지 반전될 수 있다.** 논문이
다른 모델에서 이득이 줄어드는 결과를 이미 보였다면, 교체된 질문의 답이 "이득 없음" 으로
나와도 그것은 구현 오류의 증거가 아니다. 이 사실을 `gate.md` 에 미리 기재한다.

## 4. 판정 넷

| 판정 | 조건 | 다음 |
|---|---|---|
| 구현 | 빨강 없음 | `plan` |
| 질문 교체 | 치명 아닌 빨강이 있고 교체가 성립 | `plan` — 교체된 질문으로 |
| 읽기만 | 치명 빨강, 또는 Q6~Q9 에 빨강 | `paper-tutor` 의 `read` |
| 보류 | 조건 충족 시 통과 | 조건과 확인 시점을 기재 |

`보류` 는 기한이 없으면 `읽기만` 과 같아진다. 무엇이 충족되면 다시 볼지를 함께 기재한다.

## 6. 채운 예시 — zhang-2026-saga

```markdown
# zhang-2026-saga — 구현 가치 판정

판정: 질문 교체
판정일: 2026-09-22
노트: ../study/note.md
논문 유형: B LLM 파이프라인

## 답할 질문

작은 모델에서도 type filter 의 이득이 존속하는가. 원래 질문인 "9개 설정 전부에서 F1
최고" (Table 1·2, p.6) 는 gpt-oss-120B 를 9개 데이터셋에 돌리는 비용이 예산을 넘으므로
제외하고, 절제의 방향만 확인하는 질문으로 교체하였다.

## 예산

| 항목 | 상한 |
|---|---|
| 기한 | 2주 |
| GPU 시간 | 없음 — API 만 사용 |
| API 비용 | 10만원 |
| 오를 칸 | 5칸(절제)까지. 6칸 제외 |

## 판정 근거

| # | 질문 | 판정 | 근거(앵커) |
|---|---|---|---|
| Q1 | 기여의 경계 | 초록 | 변경 대상이 `lookup` 도구의 observation 하나 (§Overview, p.2-3) |
| Q2 | 공개 시스템 델타 | 초록 | SPINACH 컨트롤러에 지침 한 덩어리와 블록 둘을 추가한 것이 전부 (§F.2, p.16). SAGA 자체 코드는 URL 미기재 (§F.3, p.18) |
| Q3 | 데이터·환경 | 노랑 | Wikidata 는 공개 endpoint(rate limit), Freebase 는 로컬 덤프로 무겁다. QALD-7 45문항(§Experiments, p.5)으로 축소 |
| Q4 | 평가 | 초록 | 실행 기반 F1·EM (§Experiments, p.5). LLM judge 아님 |
| Q5 | 실행의 결정성 | 빨강 | 본문은 greedy·temperature 0 (§Implementation Details, p.6), 부록의 컨트롤러 호출은 temperature 1.0·top-p 0.9 (§F.2, p.16). 분산·시드·반복 미보고 |
| Q6 | 절제 | 초록 | 세 기제의 절제가 Table 5 (p.7)에 있다 |
| Q7 | 축소 후 존속 | 빨강 | LLaMA-3.1-70B 로 바꾸면 SPINACH-test·WebQSP·CWQ·GrailQA 네 설정에서 SPINACH 보다 낮다 (Table 1·2, p.6) |
| Q8 | 구현으로만 답할 공백 | 초록 | empirical schema induction 과 trace-local evidence 에 절제가 없다. 같은 모델끼리의 비교표도 없다 (note.md `읽으며 든 의문`) |
| Q9 | 사용 계획 | 초록 | 사내 KG 질의 파이프라인에 적용 검토 중 |

## 범위 밖으로 제외한 주장

| 주장 | 앵커 | 제외 이유 |
|---|---|---|
| 9개 설정 전부에서 F1 최고 | Table 1·2, p.6 | 데이터셋 9개 × 베이스라인 8종 재실행이 예산 밖 |
| Freebase 로의 이전 | Table 2, p.6 | 로컬 덤프 구축이 예산 밖 |
| 스키마 결손 내성 | Table 6, p.7 | 5칸 통과 후 여유가 있으면 추가 |

## 미리 기재하는 위험

- Q7 이 빨강이므로 작은 모델에서 이득이 없게 나와도 구현 오류의 증거가 아니다. 논문 자신이
  모델을 내렸을 때 이득이 줄어드는 결과를 보인다 (Table 1·2, p.6).
- Q5 로 인해 모든 수치는 3시드 평균·표준편차로 보고한다. CWQ 의 0.20점 차(Table 2, p.6)는
  애초에 분산 안에 들어갈 수 있다.
- SAGA 코드가 없으므로 격차 원인을 저자 구현과 대조할 수 없다. `decisions.md` 가 유일한
  용의자 명단이 된다.
```

## 7. 흔한 오판

- **코드가 공개되어 있으면 쉽다고 판정하는 것.** 공개 코드가 논문과 다른 경우가 흔하다.
  Q2 가 초록이면 예산이 줄어들 뿐이고, 격차가 사라지는 것은 아니다.
- **데이터셋 이름이 익숙하면 접근 가능하다고 판정하는 것.** 같은 이름의 다른 분할이
  유통되는 경우가 있다. 논문이 지시한 분할의 출처를 확인한다.
- **절제표가 있으면 Q6 초록으로 넘기는 것.** 절제가 다루지 않은 기여 요소가 있으면
  노랑이고, 그 요소가 Q8 의 공백이 된다.
- **예산을 시간으로만 잡는 것.** B형 논문은 호출 수 × 토큰 × 단가가 비용이며, 3시드와
  절제 N개가 곱해진다. `references/plan.md` 의 산정식으로 확인한다.
- **판정을 유보하고 착수하는 것.** `gate.md` 없이 `plan` 을 시작하면 범위가 확정되지 않아
  6칸까지 올라가려는 작업이 된다.

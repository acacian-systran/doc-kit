# run — 축소 재현과 절제

사다리 4~5칸. 산출은 `runs/<날짜>-<태그>/` 와 `report.md` 다.

---

## 1. run 디렉터리 규약

**모든 실행은 `assets/run.py` 를 거친다.** 직접 실행한 결과는 3일 뒤 출처를 복원할 수
없으므로 `report.md` 에 옮기지 않는다.

```bash
cd papers/<citekey>/lab
python ../../../skills/paper-lab/assets/run.py \
  --tag baseline --config configs/tiny.yaml --seeds 0,1,2 \
  -- uv run python -m src.eval --config configs/tiny.yaml
```

`runs/<날짜>-<태그>-s<시드>/` 가 시드마다 생성되고 다음이 남는다.

| 파일 | 내용 |
|---|---|
| `env.json` | 태그·시드·git commit·dirty 여부·Python·플랫폼·패키지 목록·명령줄·시작·종료·종료코드 |
| `config.<ext>` | `--config` 로 지정한 설정 파일의 사본 |
| `stdout.log` | 표준 출력과 표준 오류 |
| `metrics.json` | **실행된 스크립트가 직접 기재한다**(§2) |

`run.py` 는 `RUN_DIR` 환경변수와 `--seed` 인자를 실행 대상에 전달한다. 스크립트는 그
디렉터리에 `metrics.json` 을 쓴다.

**`runs/` 는 추가만 한다.** 과거 run 을 수정하거나 삭제하지 않는다. 설정이 틀렸으면 새
run 을 추가하고 `report.md` 에 폐기 사유를 기재한다. 폐기한 run 을 지우면 무엇을 왜
폐기했는지가 사라진다.

## 2. `metrics.json` 계약

```json
{
  "tag": "baseline",
  "seed": 0,
  "metrics": {"f1": 31.52, "em": 8.89, "empty_rate": 34.1},
  "extra": {"cost_usd": 1.94, "mean_turns": 5.7}
}
```

`metrics` 의 키가 `claims.md` 의 `지표` 열에 백틱으로 기재된 이름과 일치해야 한다 —
`compare.py` 가 그 이름으로 대조한다. `extra` 는 대조에 쓰이지 않고 기록만 된다.

`tag` 와 `seed` 를 생략하면 `run.py` 가 남긴 `env.json` 에서 채워진다.

## 3. 절제 설계

절제가 5칸이며 **이 스킬의 성공 정의가 여기에 있다.** 논문 표의 절대 수치 일치는 대개 예산
밖이고, 절제가 논문과 같은 방향·같은 순서를 보이면 아이디어는 재현된 것으로 판정한다.

**두 부류를 구분해 태그를 부여한다.**

| 부류 | 태그 | 무엇 |
|---|---|---|
| 논문 절제 재현 | `abl-<요소>` | 논문의 절제표에 있는 항목. 방향·순서를 논문과 대조한다 |
| 추가 절제 | `xabl-<요소>` | 논문에 없는 절제. `decisions.md` 의 민감도 `높음` 항목에서 고른다 |

추가 절제는 논문 수치와 대조할 대상이 없으므로 `claims.md` 의 주장이 아니라 `report.md` 의
별도 절에 기재한다. 논문의 주장과 섞으면 독자가 둘 다 재현 결과로 읽는다.

**절제는 한 번에 하나만 제거한다.** 두 요소를 함께 제거하면 상호작용과 개별 효과가
분리되지 않는다. 논문이 함께 제거한 조건이 있으면 그 조건을 그대로 따르고 태그에 표시한다.

## 4. 시드와 분산

- **차이를 주장하려면 3시드.** 시드 하나의 결과는 `report.md` 에 `1시드` 를 병기하고
  차이 주장의 근거로 쓰지 않는다.
- **표준편차를 병기한다.** `31.52 ± 0.84 (3시드)`.
- **격차가 표준편차 안이면 차이가 없다고 기재한다.** "약간 낮다" 로 쓰지 않는다.
- **시드를 늘려 원하는 방향을 얻는 것을 하지 않는다.** 시드 수를 사전에 고정하고, 늘렸으면
  늘린 사실과 이유를 `report.md` 에 기재한다.

B형 논문은 비용이 시드 수에 비례하므로 3시드를 문항 수 축소보다 먼저 확보한다. 45문항
3시드가 135문항 1시드보다 판정에 쓸모가 있다.

## 5. 비교 표

```bash
python ../../../skills/paper-lab/assets/compare.py --tag baseline
python ../../../skills/paper-lab/assets/compare.py --delta baseline
```

첫 명령은 `claims.md` 의 주장과 `runs/` 의 실측을 대조한 표를 산출한다. 둘째는 태그마다
기준 태그와의 차이를 산출하고, 지표 키가 `Δ` 로 시작하는 주장에 **절제 주장 판정** 표를
함께 산출한다 — 논문 변화와 내 변화의 부호가 같고 차이가 분산 밖이면 그 주장은 재현된 것으로
판정한다. 5칸의 합격 판정이 이 표다.

`--delta` 가 주장과 run 을 맞추는 방식은 `claims.md` 의 두 열이다. 지표 키의 `Δ` 와
`확인 방법` 열의 첫 백틱 토큰(절제 태그). 태그를 적지 않으면 판정 행이 `태그 미기재` 로
표시된다.

산출된 표를 `report.md` 에 그대로 첨부한다. 손으로 수치를 옮기지 않는다 — 옮기는 과정에서
반올림된다.

## 6. `report.md` 템플릿

```markdown
# <citekey> — 구현 결과

판정: <gate.md 의 판정>
답한 질문: <gate.md 의 한 문장>
오른 칸: <N칸> / 목표 <M칸>
기록일: YYYY-MM-DD

## 결론

<3~5문장. 무엇을 확인했고 무엇을 확인하지 못했나. 절제의 방향이 논문과 같은지>

## 논문 주장과의 대조

<compare.py --tag 의 산출>

## 절제

<compare.py --delta 의 산출>

| 요소 | 논문 낙폭 | 내 낙폭 | 방향 | 앵커 |
|---|---|---|---|---|

## 논문에 없는 절제

<`xabl-` 태그의 결과. 논문 대조 없음을 명시한다>

## 남은 격차

| 지표 | 논문 | 내 수치 | 차이 | 용의자 순위 | 배제된 것 |
|---|---|---|---|---|---|

## 오르지 않은 칸

| 칸 | 왜 오르지 않았나 |
|---|---|

## 폐기한 run

| run | 폐기 사유 |
|---|---|
```

**`오르지 않은 칸` 절을 비우지 않는다.** 6칸을 오르지 않았으면 오르지 않았다고 기재한다.
이 절이 없으면 독자가 전체 재현으로 읽는다.

## 7. 흔한 오판

- **`run.py` 를 거치지 않고 실행한 수치를 보고하는 것.** 재현 경로가 없는 수치다.
- **절제를 여러 개 동시에 제거하는 것.** 개별 효과가 분리되지 않는다.
- **논문 절제와 추가 절제를 같은 표에 두는 것.** 독자가 둘 다 재현 결과로 읽는다.
- **1시드로 방향을 주장하는 것.** 특히 낙폭이 1점 미만일 때.
- **실패한 run 을 삭제하는 것.** 폐기 사유가 `gap` 의 입력이다.
- **수치를 손으로 옮기는 것.** `compare.py` 의 산출을 그대로 첨부한다.

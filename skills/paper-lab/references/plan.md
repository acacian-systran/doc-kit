# plan — 주장 표와 예산

게이트 통과 직후. 산출은 `claims.md` 하나이며, 이 파일의 열은 고정이다 —
`assets/compare.py` 가 이 표를 파싱한다.

---

## 1. 주장 단위로 분해

**측정 하나가 주장 하나다.** "SAGA 가 SPINACH 보다 낫다" 는 주장이 아니라 요약이다.
분해의 기준은 셋이다.

- **앵커가 하나로 지시되나.** 표 하나·행 하나·그림 하나로 지시되지 않으면 더 쪼갠다.
- **지표가 하나인가.** F1 과 EM 이 한 주장에 묶이면 둘 중 하나만 재현될 때 판정이 막힌다.
- **반증 조건을 쓸 수 있나.** "무엇이 관측되면 이 주장이 내 구현에서 성립하지 않는가" 를
  한 줄로 쓸 수 없으면 주장이 아니다.

`study/note.md` 의 `실험이 보인 것` 절은 표 앵커가 달린 측정만 담으므로 그대로 입력이 된다.
노트가 없으면 결과 절의 표를 직접 읽는다. 산문의 수치는 반올림되고 조건이 빠져 있으므로
쓰지 않는다.

**보조 지표를 빠뜨리지 않는다.** 주 지표만 담으면 방향을 확인할 수단이 하나로 줄어든다.
빈 결과 비율·행동 수·유형별 분해처럼 기제에 직결된 지표가 대개 축소판에서 더 잘 보인다.

## 2. 축소 가능성 판정

주장마다 `가능` · `불가` · `제외` 중 하나를 매긴다.

| 판정 | 조건 |
|---|---|
| 가능 | 축소 설정에서 이 주장의 방향이나 순서를 관측할 수 있다 |
| 불가 | 관측에 전체 규모가 필요하다. 이유를 함께 기재한다 |
| 제외 | 불가이며 예산 안에서 대체 관측도 없다. `gate.md` 의 제외 목록과 일치시킨다 |

**절대 수치를 요구하는 주장은 대개 `불가` 다.** 순서·방향으로 바꿀 수 있으면 주장을 다시
쓴다 — "F1 51.49" 대신 "type filter 를 제거하면 F1 이 내려간다" 로. 바꾼 주장에는 원래
주장의 앵커를 그대로 유지한다.

## 3. 예산 산정

**A형(모델·학습).**

```
GPU 시간 ≈ (축소 학습 1회 시간) × (시드 3) × (절제 항목 수 + 1)
```

미니 과적합과 성질 검사는 무시할 수 있다. 축소 학습 1회가 4시간을 넘으면 config 를 더
줄이거나 오를 칸을 4칸으로 낮춘다.

**B형(LLM 파이프라인).**

```
비용 ≈ 문항 수 × 턴 수 × (입력 토큰 + 출력 토큰) × 단가 × 시드 3 × (절제 항목 수 + 1)
```

턴 수는 논문의 행동 수 표에서 가져온다. 입력 토큰은 이력이 누적되므로 턴이 갈수록
증가하며, 평균 턴 수의 1.5배로 잡으면 대개 초과하지 않는다. 개발셋 20문항으로 한 번 돌려
실측한 뒤 전체 예산을 갱신한다 — 산정값과 실측값이 두 배 이상 벌어지는 경우가 흔하다.

**오를 칸을 예산으로 결정한다.** 예산이 5칸을 담지 못하면 4칸까지만 오르고, 그 사실을
`claims.md` 머리에 기재한다. `paper-tutor` 의 `읽은 범위` 에 대응하는 장치다.

## 4. `claims.md` 템플릿

열 이름과 순서를 바꾸지 않는다. `compare.py` 가 `#` · `지표` · `논문 수치` · `축소` 를
읽는다.

```markdown
# <citekey> — 확인할 주장

판정: <gate.md 의 판정>
답할 질문: <gate.md 의 한 문장>
오를 칸: <N칸> — 예산 근거는 gate.md
축소 설정: <모델·데이터·스텝을 어떻게 줄였나>

| # | 주장 | 지표 | 논문 수치 | 앵커 | 축소 | 확인 방법 |
|---|---|---|---|---|---|---|
| C1 | | | | | 가능 | |
| C2 | | | | | 불가 — <이유> | |

## 반증 조건

| # | 무엇이 관측되면 이 주장이 내 구현에서 성립하지 않나 |
|---|---|
| C1 | |
```

`논문 수치` 는 숫자만 기재한다. 단위·조건은 `지표` 열에 포함한다 — `compare.py` 가 숫자를
파싱한다. 수치가 없는 주장(방향만 있는 주장)은 `—` 로 둔다.

**절제 낙폭 주장은 지표 키를 `Δ` 로 시작한다.** `Δf1` 처럼. 이 주장의 `논문 수치` 는 절제
run 이 기준보다 얼마나 변했는지를 **부호까지 포함해** 기재한다 — Table 5 의 낙폭 4.97 은
`-4.97` 이다. `확인 방법` 열의 첫 백틱 토큰은 그 절제의 run 태그로 읽힌다(`` `abl-nofilter` ``).
`compare.py --delta` 가 이 셋을 맞춰 방향과 분산을 판정한다.

축소 설정: QALD-7 45문항만. Wikidata 공개 endpoint. 컨트롤러는 소형 모델. 3시드

## 6. 흔한 오판

- **주 지표만 담는 것.** 보조 지표가 기제에 더 가깝고 축소판에서 더 잘 보인다.
- **`불가` 를 `제외` 로 적는 것.** 둘은 다르다. `불가` 는 지금 예산에서 못 보는 것이고
  `제외` 는 다시 보지 않는 것이다. 예산이 늘면 `불가` 는 되살아난다.
- **논문 수치를 반올림하는 것.** 4.97 을 5.0 으로 적으면 내 낙폭 5.2 와의 차이가 사라진다.
- **반증 조건을 비워 두는 것.** 반증 조건이 없으면 `run` 의 결과를 보고 주장을 사후에
  느슨하게 고치게 된다.
- **예산을 산정값으로 확정하는 것.** 20문항 실측 후 갱신한다.

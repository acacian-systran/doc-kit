# gap — 격차 원인 좁히기

수치가 논문과 어긋났을 때. 반복 진입한다. 산출은 `report.md` 의 `남은 격차` 절 갱신이다.

이 모드의 목적은 **하이퍼파라미터를 무작정 변경하는 것의 차단**이다. 스윕은 가장 비싸고
가장 늦게 수행하는 작업이며, 스윕으로 격차가 메워지면 무엇이 원인이었는지 남지 않는다.

---

## 0. 격차 크기 판정

용의자를 세우기 전에 격차의 성격을 먼저 가른다.

| 격차 | 판정 | 다음 |
|---|---|---|
| 3시드 표준편차 안 | 차이 없음 | 조사하지 않는다. `report.md` 에 `분산 안` 으로 기재 |
| 표준편차의 1~3배 | 조건 차이 | §1 의 1~3순위 |
| 수 배 또는 방향 반전 | 구현 결함 또는 조건 반전 | §1 의 1~2순위와 성질 검사로 복귀 |
| 자릿수 | 지표·단위 오류 | 평가 코드부터. 방법을 의심하지 않는다 |

**방향 반전은 축소가 원인일 수 있다.** `gate.md` 의 `미리 기재하는 위험` 에 축소로 인한
반전 가능성을 적어 뒀으면 그것을 1순위로 올린다.

## 1. 용의자 — 확인 비용 오름차순

용의자마다 **그것을 배제하는 가장 저렴한 실험**을 병기한다. 실험이 없는 용의자는 용의자가
아니라 추측이다.

### 1순위 · 평가 스크립트

가장 저렴하고 가장 자주 맞는다. 학습이나 호출 없이 확인된다.

| 증상 | 배제 실험 |
|---|---|
| 모든 지표가 일정한 배수로 낮다 | 논문이 보고한 예제 하나의 정답을 직접 채점해 손계산과 대조 |
| F1 은 비슷한데 EM 만 크게 다르다 | 정답 정규화 규칙(대소문자·공백·순서·중복)을 하나씩 켜고 끈다 |
| 지표 구현이 여러 개인 지표다 | 같은 예측 파일을 두 구현에 넣어 차이를 잰다 |
| 빈 결과·미응답의 처리 | 빈 예측을 0점으로 세는지 제외하는지 바꿔 본다 |

**논문의 예제로 채점기를 먼저 검증한다.** 논문이 그림이나 부록에 제시한 입출력 쌍의 점수를
내 채점기가 재현하지 못하면 다른 무엇도 비교가 아니다.

### 2순위 · 데이터

논문이 분할·전처리를 명시하지 않았으면 자동으로 이 순위다.

| 증상 | 배제 실험 |
|---|---|
| 문항 수가 논문과 다르다 | 논문이 기재한 문항 수와 내 분할의 크기를 대조. 가장 빠른 신호다 |
| 같은 이름의 다른 분할 | 데이터 출처 URL 과 내려받은 날짜를 `env.md` 에서 확인. 해시 대조 |
| 전처리 차이 | 논문의 예제 입력이 내 전처리를 통과한 뒤에도 같은지 확인 |
| 필터링 | 논문이 제외한 문항 유형이 내 집합에 남아 있는지 확인 |

### 3순위 · `decisions.md` 항목

`민감도` 가 `높음` 인 항목부터 하나씩 되돌린다. 한 번에 하나만 바꾸고 각각을 새 run 으로
남긴다.

| 증상 | 배제 실험 |
|---|---|
| 특정 유형의 입력에서만 격차 | 그 유형에 관여하는 결정 항목을 찾아 되돌린다 |
| 필터·제약이 과하게 또는 약하게 동작 | 필터 전후 집합 크기를 논문이 보고한 비율과 대조 |
| 본문·부록 충돌을 한쪽으로 정한 항목 | 다른 쪽 설정으로 한 run 추가 |

**되돌린 run 의 태그에 항목 번호를 포함한다** — `gap-D3-revert`. 태그가 없으면 어느 결정을
되돌린 결과인지 복원되지 않는다.

### 4순위 · 저자 코드와 논문의 차이

코드가 공개되어 있으면 **코드와 논문의 차이 자체를 기록한다.** 흔히 다르며, 그 차이가
답인 경우가 많다. 차이를 발견하면 `decisions.md` 에 항목으로 올리고 어느 쪽을 따랐는지
기재한다.

코드가 없으면 이 순위가 비고, `decisions.md` 가 유일한 용의자 명단이 된다. 그 사실을
`report.md` 에 기재한다 — 남은 격차를 끝까지 귀속시킬 수 없다는 뜻이다.

### 5순위 · 시드와 분산

0단계에서 이미 걸렀으나, 3시드가 우연히 좁게 나오는 경우가 있다. 시드를 5개로 늘려
표준편차가 커지는지 확인한다. 늘린 사실을 기재한다.

### 순위 밖 · 하이퍼파라미터

1~5순위를 배제한 뒤에만 손댄다. 스윕을 돌릴 때는 논문이 기재한 값을 중심으로 좁게 잡고,
찾은 값이 논문 값과 다르면 그것을 결과로 보고한다 — "논문 설정으로는 재현되지 않고 lr 을
2배로 올려야 한다" 는 유용한 관측이다. 값을 조용히 바꿔 수치를 맞추는 것은 관측이 아니다.

## 2. 배제 기록

`report.md` 의 `남은 격차` 절에 누적한다.

```markdown
| 지표 | 논문 | 내 수치 | 차이 | 용의자 순위 | 배제된 것 |
|---|---|---|---|---|---|
| `f1` | 64.89 (Table 1, p.6) | 31.52 ± 0.84 (3시드, runs/2026-09-22-baseline) | −33.4 | 컨트롤러 모델 차이(1) · D3 절단 상한(2) | 평가 스크립트 — 논문 부록 예제로 채점기 검증 통과(runs/...-evalcheck) · 데이터 — 문항 수 45 일치 |
```

**배제된 것을 지우지 않는다.** 같은 격차를 다시 조사할 때 앞서 배제한 것을 다시 조사하게
된다.

## 3. 격차를 남긴 채 끝내는 경우

모든 격차가 메워지지는 않는다. 끝낼 때 다음을 기재하면 그 구현은 실패가 아니다.

- 오른 칸과 오르지 않은 칸
- 배제한 용의자와 그 근거 run
- 남은 용의자와 각각을 배제할 실험, 그 실험의 예상 비용
- 절제의 방향이 논문과 같은지 — **같으면 아이디어는 재현되었다.** 절대 수치의 격차는 그
  사실을 취소하지 않는다

## 4. 하지 말 것

- **스윕 먼저 돌리는 것.** 가장 비싸고, 메워져도 원인이 남지 않는다.
- **여러 용의자를 동시에 바꾸는 것.** 한 번에 하나, run 하나.
- **격차가 분산 안인데 조사하는 것.** 0단계를 건너뛰면 없는 원인을 찾는다.
- **논문이 틀렸다고 먼저 결론하는 것.** 1~4순위를 배제한 뒤에만 가능한 결론이며, 그때도
  "내 조건에서는 재현되지 않는다" 로 기재한다.
- **배제 기록을 지우는 것.**

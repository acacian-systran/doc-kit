# paper-lab 스펙 (v0.1 초안)

논문 한 편을 **직접 구현해 확인하는** 스킬. 구현 가치 판정(gate), 확인할 주장과 예산
확정(plan), 환경 구축과 성질 검사(build), 축소 재현과 절제(run), 수치 격차의 원인 좁히기
(gap) 다섯 모드를 한 스킬로 한정한다.

`paper-tutor` 와 짝이다. 그쪽이 논문을 읽고, 이쪽이 논문을 돌린다. 두 스킬은 citekey 하나로
이어진다.

상태: 구현 완료(2026-09-22). 동작의 기준은 `SKILL.md` 와 `references/` 이고, 이 문서는 설계 근거 기록이다.

---

## 1. 한 문장 정의

논문을 받아 (gate) 구현할 가치가 있는지 판정하고, (plan) 예산 안에서 확인할 주장을
확정하고, (build) 환경을 구축해 성질 검사까지 올리고, (run) 축소 재현과 절제를 수행하고,
(gap) 논문 수치와의 격차 원인을 좁힌다. 다섯 모드 모두 **논문에 없어서 내가 정한 것을
기록한다.**

## 2. 실패 방식과 중심 규약

`paper-tutor` 의 유일한 실패는 설명이 논문보다 확신에 찬 것이며, 앵커 규약으로 차단한다.
구현의 실패는 **코드가 동작하고 수치가 산출되었다는 이유로 논문대로 구현되었다고 믿는
것**이다. 논문은 언제나 덜 기재되어 있고 빈칸은 구현자가 메운다 — 초기화, 워밍업 스텝 수,
토크나이저, 마스크의 경계, 프롬프트 문구, 평가 스크립트. 수치가 어긋났을 때 그것이 버그인지
내가 메운 빈칸인지 논문의 과장인지 구분되지 않으면 그 구현에서는 아무것도 도출되지 않는다.

그래서 앵커의 대응물을 중심 규약으로 배치한다.

> **논문에 없어서 내가 정한 것은 코드가 아니라 `decisions.md` 에 기재한다.**

이 파일이 스킬의 본체다. 구현이 끝나면 이 목록이 격차 분석의 용의자 명단이 된다.

## 3. 형태

**스킬 하나, 모드 다섯.** 서브에이전트가 아닌 이유 — gate 의 판정과 gap 의 용의자 선별은
사용자의 예산·목적과 맞물린 판단이므로 격리 컨텍스트에서 수행할 수 없다. 장시간 실행되는
학습·평가는 백그라운드 bash 로 돌리고 결과를 `runs/` 에 파일로 남긴다. 세션을 넘어 이어지는
상태는 전부 파일이다.

## 5. 다섯 모드

### 5.1 `gate` — 구현 가치 판정

**언제.** 시작 전. 30분, 코드 없음. 입력은 논문 또는 `study/note.md`.

**판정 대상.** "재현 가능한가" 로 물으면 거의 모든 논문이 탈락한다. 판정 대상은 하나다 —
**내 예산 안에서 답이 분기할 수 있는 질문이 이 논문에 남아 있는가.** 남아 있지 않으면,
결과가 자명하거나 확인 수단이 예산 밖이므로, 구현은 코드 연습에 해당한다.

**가능성 질문** — 하나라도 빨강이면 착수하지 못한다.

| 질문 | 빨강 조건 |
|---|---|
| 기여의 경계 | 변경 대상이 시스템 전체다 |
| 공개 시스템에 대한 델타 여부 | 기준선까지 처음부터 구축해야 한다 |
| 데이터·환경 접근성 | 비공개 데이터, 사내 KB, 소실된 덤프 |
| 평가의 결정성과 비용 | 비공개 채점기, 사람 평가, LLM judge |
| 실행의 결정성 | 온도·시드 미보고 → 반복 횟수만큼 비용이 곱해진다 |

**가치 질문** — 가능해도 여기서 걸리면 구현하지 않는다.

| 질문 | 빨강 조건 |
|---|---|
| 논문의 절제 유무 | 없고, 내가 설계할 근거도 없다 |
| 축소 후 주장의 존속 | 모델·데이터를 줄이면 이득이 소멸한다 |
| 구현으로만 답할 공백 | 논문이 이미 전부 측정하였다 |
| 내 업무에서의 사용 계획 | 호기심뿐이면 `paper-tutor` 의 `read` 로 충분하다 |

**치명 빨강은 둘.** 데이터·환경 차단과 평가 재현 불가. 다른 무엇으로도 보완되지 않는다.
나머지 빨강은 대개 **질문 교체로 통과**한다. 가장 흔한 경로가 "절대 수치를 맞춘다" 를
"절제가 같은 방향·순서를 보이는가" 로 내리는 것이며, 이 교체의 성립 여부가 게이트의 실질적
판정 내용이다.

**판정 넷.**

| 판정 | 뜻 |
|---|---|
| 구현 | 논문의 주장 그대로 사다리를 오른다 |
| 질문 교체 | 축소판에서 답이 분기하는 질문으로 바꿔 오른다 |
| 읽기만 | 구현해도 도출될 것이 없거나 도출할 수 없다 |
| 보류 | 코드 공개·예산 확보 같은 조건 충족 시 통과 |

**산출.** `gate.md` — 판정, 예산(시간·비용), 실제로 답할 질문 한 문장, 범위 밖으로 제외한
주장과 그 이유, `study/note.md` 경로(있으면).

`plan` 은 판정이 `구현` 또는 `질문 교체` 일 때만 시작한다.

### 5.2 `plan` — 주장 표와 예산

**언제.** 게이트 통과 직후.

1. 논문을 **검증 가능한 주장 단위**로 분해한다. `study/note.md` 의 `실험이 보인 것` 절은
   이미 표 앵커가 달린 측정만 담으므로 그대로 입력이 된다.
2. 주장마다 축소판에서 확인 가능한지 판정하고, 불가한 것은 그 자리에서 범위 밖으로 제외한다.
3. 예산을 확정한다 — GPU 시간, API 비용, 기한. 그 예산에서 오를 수 있는 사다리 칸을 고른다.
   `paper-tutor` 의 `읽은 범위` 에 대응하는 장치다.

열 이름과 순서는 고정이다 — `compare.py` 가 이 표를 파싱한다. 절제 낙폭 주장은 지표 키에
`Δ` 를 붙이고 `확인 방법` 에 절제 태그를 기재한다.

```markdown
| # | 주장 | 지표 | 논문 수치 | 앵커 | 축소 | 확인 방법 |
|---|---|---|---|---|---|---|
| C1 | type filter 제거 시 F1 하락 | 절제 F1 변화(pt) `Δf1` | -4.97 | Table 5, p.7 | 가능 | `abl-nofilter` 절제 |
| C6 | 9개 설정 전부에서 F1 최고 | F1 | — | Table 1·2, p.6 | 제외 — 예산 밖 | — |
```

**산출.** `claims.md`

### 5.3 `build` — 환경과 성질 검사

**언제.** 주장 표 확정 후. 사다리 1~3칸(§6).

1. `papers/<citekey>/lab/` 에 독립 환경을 구축한다. 버전·장치·시드를 `env.md` 에 기재한다.
2. 구현하면서 논문에 없는 결정을 만날 때마다 `decisions.md` 에 항목을 추가한다.
   코드에 주석으로 남기지 않는다 — grep 대상이 분산되면 용의자 명단이 성립하지 않는다.
3. 성질 검사를 `tests/` 에 작성한다. 수식이 함의하는 불변량을 코드로 옮긴다.
4. 학습이 있는 논문은 미니 과적합까지 확인한다.

**`decisions.md` 항목 형식.**

```markdown
### D3 · lookup 후보 상한
- 정한 것: 원시 이웃을 200개로 절단한 뒤 Eq. 3 을 적용
- 근거: 컨텍스트 한계. 논문은 "수백 개" 만 기재하고 상한을 명시하지 않는다 (§Problem Setup, p.4)
- 논문의 공백: 절단 유무·순서·기준 모두 미기재
- 민감도: 상한이 낮으면 정답 속성 손실률이 Table 9 의 37.9% 보다 커질 수 있다
```

**산출.** `src/` · `tests/` · `env.md` · `decisions.md`

### 5.4 `run` — 축소 재현과 절제

**언제.** 성질 검사 통과 후. 사다리 4~5칸.

1. `configs/tiny.yaml` 로 시작해 순서와 방향만 확인한다.
2. 절제를 수행한다. 논문의 기여를 제거했을 때 격차가 나타나는지가 이 모드의 본체다.
3. run 마다 `runs/<날짜>-<태그>/` 에 설정·git commit·시드·환경·모델 id 를 스냅샷으로
   기록한다. 이 기록이 없으면 3일 뒤 그 수치의 출처를 복원할 수 없다.
4. 차이를 주장하려면 3시드. 시드 하나로 소수점 차이를 논하지 않는다.

**산출.** `runs/<날짜>-<태그>/` · `report.md`

### 5.5 `gap` — 격차 원인 좁히기

**언제.** 수치가 논문과 어긋났을 때. 반복 진입한다.

용의자를 **확인 비용 오름차순**으로 배열하고, 각각에 그것을 배제하는 가장 저렴한 실험을
병기한다. 하이퍼파라미터를 무작정 변경하는 것을 차단하는 것이 이 모드의 목적이다.

1. **평가 스크립트** — 지표 구현, 토크나이저, 정답 정규화. 파이프라인 논문에서 격차의 최대
   원인이며 확인이 가장 저렴하다.
2. **데이터** — 분할·전처리·필터링. 논문에 미기재면 자동으로 1순위 용의자다.
3. **`decisions.md` 항목** — 결과에 민감할 것부터.
4. **저자 코드와 논문의 차이** — 코드가 공개되어 있으면 그 차이 자체를 기록한다. 흔히
   다르며, 그 차이가 답인 경우가 많다.
5. **시드** — 3시드의 분산 안에 들어가는 격차인지 먼저 확인한다.

**산출.** `report.md` 갱신 — 오른 칸, 비교 표, 남은 격차와 용의자 순위.

## 6. 사다리

칸마다 저렴하고 명확한 합격 조건이 있으며, 아래 칸이 통과되지 않으면 위로 오르지 않는다.
논문 유형에 따라 칸의 내용이 분기한다.

**A형 · 모델·학습 논문**

| 칸 | 확인 | 비용 |
|---|---|---|
| 1 형상 | forward 가 실행되고 출력 shape 이 식과 일치하나 | 초 |
| 2 성질 | attention 행 합이 1, causal 마스크가 미래를 차단, permutation equivariance, grad 가 모든 파라미터에 도달 | 초 |
| 3 미니 과적합 | 8개 배치를 암기하나. 실패하면 학습 코드의 결함 | 분 |
| 4 축소 학습 | 장난감 데이터·작은 config 로 순서와 방향 확인 | 시간 |
| 5 절제 | 논문의 기여를 제거하면 격차가 나타나나 | 시간 |
| 6 전체 재현 | 표의 절대 수치 | 대개 예산 밖 |

**B형 · LLM 파이프라인·에이전트 논문**

1칸 예제 하나를 수동 통과 → 2칸 형식 성질(생성 결과가 파싱되나, 스키마에 없는 식별자를
사용하나) → 3칸 개발셋 20문항 → 4칸 전체 개발셋 → 5칸 절제. 미니 과적합이 없고, 비용과
모델 버전이 변수다. run 마다 모델 id·온도·프롬프트 해시를 기록하지 않으면 어제 수치와
오늘 수치를 비교할 수 없다.

**C형 · 시스템·커널 논문** — 1칸이 정확성 동치 검사이며 본체는 측정 방법론(워밍업, 반복,
분산 보고)이다. **D형 · 이론 논문** — 구현이 아니라 수치 검증과 반례 탐색이다.

**성공의 정의를 절제에 둔다.** 개인이 논문 표의 절대 수치를 일치시키는 일은 거의 불가능하며
목적도 아니다. 5칸이 논문과 같은 방향·같은 순서를 보이면 아이디어는 재현된 것으로 판정한다.
이 정의를 고정하면 산출이 "재현 실패" 대신 "3칸까지 도달, 절제는 같은 방향, 절대 수치는
3.1 낮음" 이 된다.

## 7. 공통 규약

- **논문에 없어서 정한 것은 `decisions.md` 에.** 코드 주석에 남기지 않는다.
- **측정과 추정을 가른다.** `paper-tutor` 의 측정·주장 분리와 같다. `report.md` 의 수치는
  `runs/` 의 어느 run 에서 왔는지 태그로 지시한다.
- **논문 수치는 앵커와 함께 인용한다.** `claims.md` 의 앵커를 그대로 옮긴다.
- **축소한 조건은 수치와 같은 문장에.** 모델·데이터·스텝을 줄였으면 그 사실이 결과의
  일부다.
- **시드 하나로 차이를 주장하지 않는다.** 3시드, 분산 병기.
- **`runs/` 는 추가만 한다.** 과거 run 을 수정하거나 삭제하지 않는다. 설정이 틀렸으면
  새 run 을 추가하고 `report.md` 에 폐기 사유를 기재한다.
- **`_shared/` 를 작성하지 않는다.** 두 논문이 같은 유틸리티를 사용해도 복사한다. 공유하면
  논문 A 를 위한 수정으로 논문 B 의 과거 run 이 재현 불가가 된다.
- 문체는 `korean-report-style`. `.md` 산출물은 평서체다.

```
papers/                          # 두 스킬이 공유하는 유일한 루트
  README.md                      # 색인 — citekey · 게이트 판정 · 오른 칸 · 한 줄 결론
  .gitignore                     # runs 의 대용량 산출물 · 체크포인트 · .venv
  <citekey>/                     # citekey = 제1저자성-연도-제목첫단어
    study/                       # paper-tutor 산출
      paper.pdf · paper.txt
      glossary.md · qa.md · note.md · quiz.md
    lab/                         # paper-lab 산출
      gate.md · claims.md · decisions.md · env.md · report.md
      pyproject.toml · uv.lock   # 논문마다 따로
      src/ · tests/ · configs/
      runs/<날짜>-<태그>/
```

**환경 격리가 이 배치의 실질적 이유다.** 논문 A 가 torch 2.1, B 가 2.5 를 요구하는 경우가
흔하며, 루트에 venv 하나를 배치하면 두 번째 논문에서 첫 번째가 무너진다. 각 `lab/` 을
독립 프로젝트로 취급한다.

**호스트 프로젝트 오염 차단.** `papers/` 밖에 아무것도 기재하지 않는다. 무시 규칙은
`papers/.gitignore` 안에서 처리한다. `runs/*/metrics.json` 과 설정 스냅샷은 커밋하고
체크포인트·원본 로그는 무시한다 — 이 구분이 없으면 첫 학습에서 저장소가 GB 단위로
증가한다.

**이름 충돌.** 받아 쓰는 프로젝트에 `papers/` 가 이미 존재하면 내용을 확인하고 사용자에게
묻는다. 다른 이름을 쓰기로 하면 그 루트의 `README.md` 머리에 경로를 기재해 다음 세션이
찾게 한다.

**`paper-tutor` 경로 변경.** 기존 `notes/papers/<citekey>/` 를 `papers/<citekey>/study/` 로
이전한다. `paper-tutor` 의 SKILL.md §2.1 과 SPEC.md §7 을 함께 수정한다.

## 9. 재사용 자산의 범위

아무 논문에나 적용되는 하네스를 구축하려 하면 PyTorch Lightning 의 열등한 사본이 산출된다.
논문마다 구현이 다르므로 추상화되지 않는다. 재사용 대상은 셋으로 한정한다.

| 자산 | 역할 |
|---|---|
| `assets/run.py` | run 디렉터리 생성 + 설정·commit·시드·환경·모델 id 스냅샷 |
| `assets/compare.py` | `runs/` 와 `claims.md` 를 읽어 `내 수치 · 논문 수치 · 앵커 · 차이` 표 생성 |
| `references/build.md` | 논문 유형별 성질 검사 카탈로그. 추상 클래스가 아닌 예시 모음 |

나머지는 전부 논문별 코드이며 추상화하지 않는다.

## 10. 모드 선택

| 요청에 있는 말 | 모드 |
|---|---|
| 구현할 만해 · 해볼 가치 · 재현 가능해 · 판단 | gate |
| 뭘 확인할지 · 계획 · 예산 · 범위 | plan |
| 환경 · 구현 · 테스트 · 짜 줘 | build |
| 돌려 · 실험 · 절제 · ablation | run |
| 수치가 안 맞아 · 왜 다르지 · 격차 | gap |
| 논문만 주고 "구현해 줘" | **gate 부터 시작한다.** 판정 없이 착수하지 않는다 |

`lab/gate.md` 가 이미 있으면 그 판정을 먼저 제시하고 다음 모드로 넘어간다.

## 11. 범위 밖

- 논문 읽기·요약·용어집·퀴즈 — `paper-tutor`
- 논문 탐색·추천 — alphaXiv 등은 원문 확보에만
- 전체 규모 재현 — 예산 밖임을 `gate` 에서 명시하고 제외한다
- 여러 논문 비교 벤치마크 — v2
- 학습 인프라(분산 학습, 클러스터 스케줄러) — 범위 밖
- 논문 방법의 제품화 — 이 스킬의 산출은 실험 코드다

## 13. 완성 확인

파일럿은 `zhang-2026-saga` 다. 게이트를 돌린 결과가 **질문 교체**였다 — 절대 수치는 범위
밖이고, 남는 질문은 "작은 모델에서도 type filter 의 이득이 존속하는가" 이다. 코드가 공개되지
않아 `decisions.md` 가 두꺼워지고, 절제가 논문의 기여 자체이며(Table 5, p.7), 축소가 주장을
반전시킬 수 있다(Table 1·2, p.6). 스킬이 실제로 감당해야 할 조건이 모여 있다.

- [ ] `gate` 가 `zhang-2026-saga` 를 `질문 교체` 로, 치명 빨강 논문을 `읽기만` 으로 가르나
- [ ] `claims.md` 의 주장마다 앵커와 `축소에서 가능/불가` 판정이 있나
- [ ] `decisions.md` 항목이 10개 이상 도출되나. 코드 주석에 숨은 결정이 없나
- [ ] `tests/` 가 Eq. 3 의 두 통과 조건과 τ(e) = ∅ 예외를 검사하나
- [ ] `runs/` 스냅샷만으로 3일 뒤 같은 수치를 재현할 수 있나
- [ ] `report.md` 가 오른 칸과 범위 밖 주장을 명시하나. 절대 수치를 재현하였다고 기재하지
      않나
- [ ] `gap` 이 용의자를 비용 오름차순으로 배열하고 배제 실험을 병기하나
- [ ] 노트가 없는 논문(`sharma-2025-reducing`)에서도 `gate` 가 단독 동작하나
- [ ] `./install.sh` 후 `~/.claude/skills/paper-lab` 이 연결되나

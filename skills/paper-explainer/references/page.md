# 페이지 구성

## 1. Overview (`index.html`)

| 블록 | 내용 | 분량 |
|---|---|---|
| 머리 | 논문 원제 · 한국어 부제 · 저자·연도·출처 · 읽은 범위 | — |
| 한 화면 요약 | **문제** · **핵심 아이디어** · **주요 결과** 소제목 셋 | 각 2~4문장 |
| 논문의 흐름 | `<ol id="flow">` — `site.js` 가 `sections.js` 로 그린다. 손으로 쓰지 않는다 | — |
| 읽는 법 | 추천 순서, 건너뛰어도 되는 곳, 합치거나 뺀 섹션 | 3~6줄 |

주요 결과의 수치는 표에서 가져오고 앵커를 단다(`<span class="src">Table 2, p.8</span>`).

## 2. 챕터 페이지 (하위 챕터가 있는 경우)

하위 챕터들의 **지도**다. 내용을 미리 다 설명하지 않는다.

1. 이 챕터가 답하는 질문 (`.question`)
2. 챕터 도입부(하위 챕터 앞의 원문)의 해설
3. 하위 챕터 각각이 맡은 역할 한두 줄씩 — 서로 어떻게 맞물리는지
4. 전체 구조 그림이 있으면 여기 (예: 아키텍처 전체도). 하위 챕터 페이지에서 그 그림의
   일부를 다시 쓸 때는 같은 그림에서 해당 부분만 강조한다

## 3. 섹션 페이지

순서는 고정이다. 각 블록의 클래스는 `common/site.css` 에 있다.

1. **머리** — `.crumb`(자동), `h1`(원문 번호 + 원제), `.question`, `.anchor`
2. **앞에서** `.bridge` — 직전 섹션이 남긴 것 한두 문장. 이 섹션이 왜 필요한지로 이어지게
3. **본문** — 아래 규칙
4. **다음에서** `.bridge` — 이 섹션이 다음 섹션에 넘기는 것
5. `<nav class="pager" id="pager">` — 비워 둔다. 자동

### 본문 규칙

- **원문 순서를 따라가며 해설한다.** 문단 요약이 아니라, 원문의 각 주장·식·그림이
  무엇을 하는지 독자 수준에서 풀어 쓴다.
- **수식**: `$$ ... $$` 로 쓰고, 바로 아래 `<dl class="symbols">` 로 기호마다 의미를 단다.
  기호 표 없이 수식을 두지 않는다. 식이 여러 단계로 만들어지면 단계 풀이(motion.md §2)로.
- **그림**: 원문 그림을 그대로 옮기지 않는다. 설명에 필요한 부분만 HTML/SVG 로 다시 그리고
  `원문 Figure N 을 단순화` 라고 적는다.
- **장난감 예시**: 메커니즘 섹션에는 작은 숫자로 손계산할 수 있는 예를 하나 넣는다.
  논문에 없는 예시이므로 `.callout.outside` 로 감싼다.
- **원문 위치**: 수치·표·그림·인용마다 `<span class="src">Table 2, p.8</span>`.
- **측정과 주장**: 결과를 말하는 문장 앞에 `<span class="result">측정</span>`,
  저자의 해석에는 `<span class="claim">저자 주장</span>`. 결과 섹션에서는 필수,
  다른 섹션에서는 둘이 한 문단에 섞일 때만.
- **논문 밖 설명**: 배경 지식·비유·장난감 예시는 `<div class="callout outside">
  <span class="callout-title">논문 외 설명</span>…</div>` 또는 문장 앞 `<span class="outside-tag">논문 외</span>`.
- **핵심 정리**: 섹션의 요점 하나를 `.callout.key` 로. 섹션당 하나.
- 분량: 하위 챕터 페이지는 화면 2~5개. 메커니즘의 핵심 섹션은 제한 없음.

### 용어

영어 원문이 본문 용어다. 정착된 번역어만 첫 등장에 괄호 병기 — `attention(주의)`.
억지 번역어를 만들지 않는다. 문체는 -다체 설명문 (`korean-report-style`).

**논문이 이름을 붙인 개념은 원문 그대로 쓴다.** 다음은 논문의 고유 명칭이므로 번역하지 않는다.

- 문단 맨 앞의 굵은 소제목(run-in heading) — `Textual Documentation.` `Target Output.` `Retry mechanism.`
- 기호를 붙여 정의한 구성 요소 — `Textual Documentation D`, `External Ontology Repository E`
- 번호·기호 목록의 항목 이름 — 보강 작업 `Value documentation`, 평가 `Expert Evaluation`, 조건 `Schema Coverage`
- 페이지의 h2·h3 가 원문 소제목에 대응하면 원문 소제목을 그대로 쓴다

본문에서 다시 부를 때는 논문이 본문에서 부르는 형태를 따른다(`the documentation` → `documentation`).
그 개념을 풀어 설명하는 서술, 논문 밖의 일반 개념(관계형 스키마 일반, 클래스 계층 일반)은 한국어로 쓴다.
쓰기 전에 원문에서 run-in heading 과 목록 항목 이름을 뽑아 두고 그 목록과 대조한다:

```bash
awk '/^\[\[p\./{p=$0} /^([A-Z][A-Za-z-]*( [A-Za-z-]+){0,4})\. [A-Z]/ {match($0,/^[^.]*\./); print p, substr($0,1,RLENGTH)}' paper.txt
grep -oE '^[0-9a-d][.)] [A-Z][A-Za-z ]+:' paper.txt
```

영어 단어 뒤 조사는 읽는 소리의 받침에 맞춘다 — documentation(-션)·Output(-풋)·Evaluation(-션) 은
`은/을/이/과`, alignment(-트)·hierarchy(-키)·Repository(-리) 는 `는/를/가/와`.

**논문의 연구 대상을 문서 요소와 같은 한국어로 쓰지 않는다.** DB 논문의 relational table 을
`표` 로 쓰면 원문 Table N · 비교 표 · 기호 표와 뒤섞여, 문장마다 어느 표인지 다시 읽어야 한다.
연구 대상은 `테이블` · `컬럼` 처럼 외래어로 쓰고, `표` · `열` 은 원문 Table N 과 페이지 안의 표에만 쓴다.
같은 충돌이 생기는 다른 예: 그래프 DB 의 graph ↔ 페이지의 차트, 연구 대상인 figure ↔ 원문 Figure N.
바꿀 때는 조사도 받침에 맞춘다 (표는 → 테이블은, 표를 → 테이블을, 표가 → 테이블이, 표와 → 테이블과, 표다 → 테이블이다, 열로 → 컬럼으로).
`표다` · `표일수록` 처럼 서술격 조사가 붙은 형태도 놓치지 않게 찾는다.

## 4. 페이지 전용 스타일

여러 페이지가 쓰는 규칙은 `common/site.css` 에만 둔다. 한 페이지에만 있는 도식(질의 조각,
검색 결과 카드 등)의 스타일은 그 페이지 `<head>` 의 `<style>` 에 쓰되, 색은 `var(--accent)`
같은 토큰만 쓴다. 색을 직접 쓰면 다크 모드에서 깨진다. 같은 도식이 두 페이지에 나오면
`site.css` 로 옮긴다.

## 5. 표

`<div class="tbl-wrap"><table>…<caption>원문 Table N 에서 발췌 · p.N</caption></table></div>`.
기본 스타일은 `site.css` 에 있다 — 숫자 열은 `td.n`, 강조 행은 `tr.hl`. 원문 표를 옮길 때는
값을 레이아웃 추출본(`--layout`)에서 가져오고 반올림하지 않는다.

## 6. 읽으며 든 의문

원문을 대조하다 발견한 서술의 빈칸·불일치는 페이지 끝(다음에서 앞)에 `읽으며 든 의문` 절로
모은다. 항목마다 근거 앵커를 단다. 이것은 논문 밖 지식이 아니라 원문 대조 결과이므로
`논문 외` 표시를 붙이지 않는다. 추정이 섞이면 `추정:` 으로 시작한다.

# 노드 형식 (공용 기본값)

`wiki.config.md`의 "노드 종류" 절이 다르게 정한 종류는 그쪽을 따른다.

## 모든 노드

- 노드 하나 = 개념 · 결정 · 결과 하나. 둘을 설명하게 되면 나눈다.
- 파일 이름: 제목을 짧게, 띄어쓰기는 `-`. 영어 용어는 원문 표기(`OWL-2-DL.md`, `punning.md`).
- frontmatter:
  ```yaml
  ---
  type: <폴더 이름과 같음>
  aliases:
    - <검색어: 원어 · 번역어 · 약어 · 코드 이름>
  ---
  ```
- 제목은 `# <용어 또는 질문>` 하나.
- 링크는 표준 Markdown 상대 경로(`[class](class.md)`, `[결정](../결정/x.md)`). GitHub · Obsidian 모두 동작. `[[wikilink]]` 쓰지 않음.
- 숫자 · 사실은 근거 파일(config `evidence`)과 원문(config `sources`)에서만. 근거에 없는 원인 설명은 "추정"이라고 쓰거나 뺀다.
- 맨 끝 `## 원문`에 숫자가 나온 파일을 링크. 장 · 절 · 표 번호까지.

## 개념 (용어 하나)

짧게. 화면 한 장 안.

```markdown
# <용어>

**한 줄로:** <정의 한 문장. 이 프로젝트에서 무엇을 가리키는지까지>

| | 내용 |
|---|---|
| 정의 / 표준에서 | ... |
| 이 프로젝트에서 | 어디에 나오는가(판정 항목 · 지표 · 단계) |
| 예 | 실제 데이터 · 실행 결과에서 하나. 파일에서 확인한 것만 |
| 생기는 이유 / 세는 법 | 해당될 때 |
| 무엇이 아닌가 | 자주 헷갈리는 이웃 개념과의 경계 |

**숫자:** 조건 · 기법별 값. 평균이면 run별 값을 괄호로.

**주의:** 오해하기 쉬운 점, 본문에서 다루지 않는다는 사실 등.

## 관련

- 이웃 노드 링크

## 원문

- 근거 파일 · 원문 장 · 절
```

비교 대상이 둘이면 표를 두 열로(`| | A | B |`).

## 헷갈린 점 (질문 하나)

```markdown
# <질문 그대로 — "X와 Y는 왜 따로 있나">

**답:** <두세 문장. 첫 문장이 바로 답>

**왜 헷갈렸나:** 어느 문서의 어느 절을 읽다가, 어떤 표기 때문에. (날짜, 맥락)

## 한눈에

| | X | Y |
|---|---|---|

## 관련 / ## 원문
```

## 결정

```markdown
# <결정 이름>

**무엇:** 정한 내용.
**왜:** 이유 · 누가 정했나(사용자 결정이면 그렇게).
**확인:** 정하기 전에 확인한 것과 결과.
**영향:** 바뀐 문서 · 수치 · 다음 일.

## 관련 / ## 원문
```

## 결과

```markdown
# <결과 한 줄>

**답하는 질문:** <연구 질문 · 하위 질문>
**답:** 한두 문장.

| 조건 | 값 | ... |

**해석:** 근거가 받쳐 주는 만큼만. 원인이 확정이 아니면 "후보".

## 관련 / ## 원문
```

## 한계

`**무엇:**` → `**왜 생겼나:**` → `**영향:**`(어느 결과를 얼마나 흔드나) → `**대응 / 향후 과제:**`.

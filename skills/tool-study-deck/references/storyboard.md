# storyboard — 장별 역할

OOPS! 소개 덱(6장: 정의 → 필요성 → 대표 오류 → 결과 읽기 → 비교 → 절차)을 뼈대로 삼고,
실행 장면과 Common Language 를 더한 15장 구성. 도구에 따라 장을 합치거나 빼되 순서는 지킨다.

| # | 역할 | 화면 | HermiT 덱 |
|---|---|---|---|
| 1 | 표지 | 도구 이름 크게, "한 줄 정체 · 예시 영역" 작게. 그 외 없음 | HermiT / OWL 2 추론기 · 공항 온톨로지로 보는 동작 |
| 2 | 기본 요소 | 비개발자용 기초 개념 3~4개를 같은 크기 카드로, 예시 영역의 실물로 | 클래스 · 개체 · 속성 · 공리 |
| 3 | 전과 후 | 도구를 돌리기 전/후를 나란히, 바뀐 곳만 강조색 | 적어 둔 계층 → 추론된 계층 |
| 4 | 도구가 답하는 질문 | 기능 3~5개를 "질문 + 예시 → 결과 칩" 카드로 | 일관성 · 분류 · 만족 가능성 · 개체 분류 |
| 5–6 | 오류 신호 | 장면 하나씩, 입력 → 결과 흐름. 비슷한 두 신호는 비교표로 차이 | 만족 불가 클래스, 불일치 온톨로지 |
| 7 | 결과 읽는 법 | 실제 UI 의 표시 3가지와 점검 순서 | 알림 창 · 빨간 클래스 · 연노랑 배경 |
| 8–10 | 놀라는 결과 | 장마다 "흔한 기대 vs 실제 출력 → 고치는 법" | 도메인 교집합 · 열린 세계 · 고유 이름 가정 |
| 11 | 동작 원리 | 단계 흐름 4칸, 비개발자도 따라올 수준 | 반례 만들기 → 모순 → 결론 |
| 12 | 비슷한 도구 비교 | 표 4행 이내 + 예시 영역에 대입한 한 줄 | HermiT · Pellet · ELK |
| 13 | 짝 도구와 역할 | 도구 3개 카드, 같은 예시 영역에서 무엇을 잡나 | OOPS · HermiT · SHACL |
| 14 | 실무 절차 | 단계 카드 5~7개 + 코드로 돌릴 때 4줄 | Protégé 6단계 + owlready2 |
| 15 | Common Language | BEFORE(막연한 말) → AFTER(정확한 용어 + 짧은 풀이) 5줄 | "에러 났다" → 불일치 |

## 배치 규칙

- 놀라는 결과(8–10)는 오류 신호와 결과 읽는 법 뒤에 둔다. 신호를 읽을 줄 알아야 의외성이 보인다.
- 짝 도구 슬라이드(13)는 앞 장면을 재사용한다. 새 예시를 만들지 않는다.
- 동작 원리(11)에는 도구의 대표 논문이 말하는 핵심 아이디어 하나만. 나머지는 노트 `(시간 남으면)`.
- 각 섹션 첫 슬라이드에 `data-section` 을 단다 (무엇·오류 신호·놀라는 결과·원리와 관계·실무).

## 용어집 (`deck/glossary.md`)

세 칸: English · 한글 표기 · 짧은 풀이(비개발자용). 한글 표기는 번역어나 뜻풀이이고
음차가 아니다(Tableau → "반례 만들기 방식"). 대본의 `English(한글)` 괄호에 이 칸을 쓴다.

## 변형: 안내판 허브

실행 장면이 5개 이상이면 4번 자리에 **결과 모음 한 장**(장면 · 결과 · 상태 · 자세히 볼 슬라이드 번호)을
두고, 이후 슬라이드가 그 행을 하나씩 펼치게 한다. 첫 장 바로 뒤에는 "적어 둔 문장 → 따라 나온 문장"
한 장으로 도구가 하는 일을 먼저 보여 주고, 기초 개념은 그 다음에 한 장의 표로 정리한다.
HermiT 공항편(`deck2/`)이 이 구성이다: 표지 · 적은 것과 따라 나온 것 · 재료 · 안내판 · 분류 ·
운항 불가와 폐쇄 · 화면 읽기 · 예상 밖 ×3 · 반례 찾기 · 관할 구역 · 점검 동선 · 돌리는 방법 · Common Language.

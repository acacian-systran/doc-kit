# quiz — 이해 확인

읽은 뒤 이해했는지를 **대화로** 확인한다. 한 문제씩 내고, 답을 듣고, 채점하고, 다음으로.
시험지를 한 번에 던지지 않는다 — 틀린 자리에서 바로 원문으로 돌려보내는 것이 목적이다.

## 1. 문제의 씨앗

세 곳에서 온다. 있는 것부터 쓴다.

| 씨앗 | 어디서 | 어떤 문제가 되나 |
|---|---|---|
| glossary 의 `점검` 줄 | `glossary.md` | 사실 · 이유 |
| note 의 `읽으며 든 의문` | `note.md` | 적용·비판 |
| 결과·ablation 표의 행 | `paper.txt` 의 `--layout` 추출 | 사실 · 적용 |

glossary 도 note 도 없으면 `paper.txt` 에서 직접 만든다. 방법 절의 설계 결정과 결과 표가
가장 좋은 재료다.

## 2. 세 유형

셋을 섞는다. 사실만 내면 암기 시험이 되고 비판만 내면 논문을 안 읽고도 답한다.

| 유형 | 묻는 것 | 예 (1706.03762) | 정답 앵커 |
|---|---|---|---|
| **사실** | 무엇을 했고 무엇을 얻었나 | EN-DE 에서 Transformer (big) 의 BLEU 와, 기존 최고와의 차이는? | 28.4, 기존 앙상블 26.36 대비 2.0 이상 (Table 2, p.8) |
| **이유** | 왜 그렇게 설계했나. 저자의 근거는 | dot product 를 √dk 로 나누는 이유로 저자가 든 것은? | dk 가 크면 dot product 분산이 커져 softmax 가 gradient 가 작은 영역으로 밀린다 (§3.2.1 · 각주 4, p.4) |
| **적용·비판** | 조건이 바뀌면. 저자가 보이지 않은 것은 | head 수를 늘리면 항상 좋아지나? 표에서 근거를 들어라 | 아니다. Table 3 (A): h=1 → 24.9, h=8 → 25.8, h=16 → 25.8, h=32 → 25.4. "quality also drops off with too many heads" (§6.2, p.9) |

**모든 문제에 정답과 앵커.** 원문으로 확인할 수 없는 문제는 내지 않는다. 적용·비판 유형도
"논문의 어느 표·절로 판단하는가" 가 명확해야 한다. "이 방법이 좋다고 생각하나?" 는 문제가
아니다.

**난이도.** 사용자가 지정하면 따른다.

| 수준 | 사실 : 이유 : 적용 | 특징 |
|---|---|---|
| 입문 | 3 : 2 : 0 | glossary 의 점검 줄 중심 |
| 표준 (기본) | 2 : 2 : 1 | |
| 심화 | 1 : 2 : 2 | ablation 표 해석, 저자가 보이지 않은 것 |

기본 5문제.

## 3. 진행

```
[1/5] <문제>                              ← 유형은 밝히지 않는다. 밝히면 힌트가 된다
(사용자 답)
맞음 / 부분 — <무엇이 빠졌나> / 틀림
  틀림 → 힌트: <다시 볼 절·표를 앵커로. 정답은 주지 않는다>
  (사용자 재답)
  두 번째도 틀림 → 정답 + 해설 + 앵커
[2/5] ...
```

**채점.**
- **맞음** — 핵심이 있으면 표현이 달라도 맞음. 수치는 반올림을 허용하지 않는다(28 은 틀림,
  28.4 가 맞음). 단 사용자가 "28 정도" 라고 했으면 "28.4" 를 알려 주고 맞음으로.
- **부분** — 절반 이상 맞았지만 빠진 것이 있다. 무엇이 빠졌는지 말하고 그 부분만 다시 묻는다.
- **틀림** — 핵심이 틀렸거나 다른 논문·일반 지식과 섞였다.

**힌트는 위치다, 답이 아니다.** "§3.2.1 마지막 문단과 각주 4 를 다시 봐" 가 힌트다.
"softmax 와 관련이 있어" 는 반쯤 답이다. 힌트는 한 번.

**두 번째 오답에는 정답·해설·앵커를 다 준다.** 세 번 묻지 않는다 — 그건 시험이 아니라 괴롭힘이다.

**대화는 대화체.** "맞아요. Table 2 에서 28.4, 기존 앙상블 최고 26.36 이니 2.04 차이죠."
파일에 적을 때만 문서체.

## 4. 마무리

5문제가 끝나면:

1. 결과 한 줄 — `4/5. 틀린 것: 2번(이유)`.
2. **오답이 몰린 개념**을 짚는다. 틀린 문제의 앵커가 같은 절에 몰리면 그 절이 약한 곳이다.
3. glossary 의 어느 항목, 논문의 어느 절로 돌아갈지 알린다.

> 3/5. 틀린 두 문제가 모두 §3.2 attention 계산이었어요. glossary 의 `softmax` 와
> `scaled dot-product attention` 을 다시 보고 §3.2.1 (p.4) 를 읽은 뒤 다시 풀어 보면 좋겠어요.

## 5. 기록 형식 (`quiz.md`)

문제은행과 회차 기록을 한 파일에. 복습 때 "전에 틀린 것부터" 를 하려면 어느 문제를 언제
어떻게 틀렸는지가 남아야 한다.

```markdown
# <원제> — 퀴즈

## 문제은행

### Q1 · 사실 · 표준
EN-DE 에서 Transformer (big) 의 BLEU 와 기존 최고 대비 차이는?
- 정답: 28.4. 기존 최고(ConvS2S Ensemble 26.36)보다 2.0 이상 (Table 2, p.8)
- 힌트: Table 2 (p.8) 의 EN-DE 열

### Q2 · 이유 · 표준
dot product 를 √dk 로 나누는 이유로 저자가 든 것은?
- 정답: dk 가 크면 dot product 의 분산이 dk 로 커져 softmax 가 gradient 가 매우 작은
  영역으로 밀린다 (§3.2.1 · 각주 4, p.4)
- 힌트: §3.2.1 마지막 문단과 각주 4 (p.4)

...

## 회차

| 날짜 | 문제 | 결과 | 비고 |
|---|---|---|---|
| 2026-09-18 | Q1 | 맞음 | |
| 2026-09-18 | Q2 | 힌트 후 맞음 | 처음엔 "수치 안정" 만 답함 |
| 2026-09-18 | Q3 | 틀림 | head 늘리면 항상 좋아진다고 답함 |
```

다음 회차를 시작할 때 `회차` 표에 `틀림` 또는 `힌트 후 맞음` 이 있으면 "전에 틀린 Q2, Q3
부터 다시 볼까요?" 를 제안한다. 새 문제를 낼 때는 문제은행에 덧붙이고 번호를 이어 간다.

## 6. 자주 하는 실수

- **정답을 힌트에 넣는다.** 힌트는 위치.
- **유형을 문제 앞에 쓴다.** "(이유) 왜 ~" 는 답의 방향을 알려 준다. 기록에만 적는다.
- **논문 밖 문제.** "Transformer 이후 어떤 모델이 나왔나" 는 이 논문 퀴즈가 아니다.
- **의견 문제.** "이 방법이 좋다고 생각하나" 는 채점할 수 없다.
- **한 번에 5문제를 던진다.** 그러면 틀린 자리에서 원문으로 돌려보낼 수 없다.

# read — 노트

읽은 뒤 남기는 노트. 심사자의 노트가 아니라 **학습자의 노트**다 — "이 논문이 무엇을
주장하나" 보다 "이 아이디어가 어떻게 작동하나" 에 답한다. 그래서 핵심 아이디어 절이
본체이고 분량 제한이 없다. 나머지 절은 3~5문장 — 넘어가면 요약이 아니라 번역이다.

## 1. 머리말

프런트매터는 나중에 grep 과 목록 생성에 쓴다. 값을 모르면 키를 지우지 말고 비운다 —
키가 사라지면 "확인 안 함" 인지 "없음" 인지 구별되지 않는다.

## 3. 채운 예시 — 핵심 아이디어 절 (1706.03762)

다른 절은 형식이 자명하므로 본체인 핵심 아이디어 절만 보인다. 이 절이 하이퍼파라미터
나열이 아니라 **계산의 흐름**이어야 한다는 것을 본다.

```markdown
## 핵심 아이디어

구조는 encoder-decoder 다 (Figure 1, p.3). encoder 는 같은 층 6개를 쌓고, 각 층은
multi-head self-attention 서브층과 position-wise feed-forward 서브층으로 되어 있다. 모든
서브층은 `LayerNorm(x + Sublayer(x))` 로 감싸며, 이 덧셈 때문에 모든 서브층 출력이
d_model = 512 로 고정된다 (§3.1, p.3). decoder 는 여기에 encoder 출력을 보는 세 번째
서브층이 끼고, self-attention 에 마스크가 걸려 위치 i 가 i 이후를 보지 못한다 (§3.1, p.3).

**attention 이 무엇을 계산하나.** query 하나와 key-value 쌍 여러 개를 받아, query 와 각
key 의 유사도를 가중치로 삼아 value 를 가중합한다 (§3.2, p.3). 이 논문의 유사도는 dot
product 를 √dk 로 나눈 것이고, 가중치는 softmax 로 만든다:

    Attention(Q, K, V) = softmax(QKᵀ / √dk) V        (Eq. 1, p.4)

√dk 로 나누는 이유를 저자가 밝힌다 — dk 가 크면 dot product 의 분산이 dk 로 커져
softmax 가 gradient 가 거의 없는 영역으로 밀린다 (§3.2.1 및 각주 4, p.4). 기존의
additive attention 은 이 문제가 없지만 행렬곱으로 구현되는 dot product 가 훨씬 빠르다는
것이 선택 이유다 (§3.2.1, p.4).

**multi-head.** attention 을 한 번 하지 않고, Q·K·V 를 h 개의 서로 다른 학습된 선형 사상
W_i^Q, W_i^K, W_i^V 로 보내 h 번 병렬로 하고 결과를 이어 붙여 W^O 로 다시 사상한다
(§3.2.2, p.4-5). h = 8, dk = dv = d_model/h = 64 이므로 총 계산량은 단일 head 와
비슷하다 (§3.2.2, p.5). 저자가 든 이유는 단일 head 의 평균화가 "different representation
subspaces at different positions" 를 함께 보는 것을 막는다는 것이다 (§3.2.2, p.5).

**어디에 쓰이나.** 세 자리다 (§3.2.3, p.5). encoder self-attention 은 Q·K·V 가 모두 이전
encoder 층 출력. decoder self-attention 은 같되 미래 위치를 softmax 입력에서 −∞ 로
마스크. encoder-decoder attention 은 Q 가 decoder, K·V 가 encoder 출력.

**순서 정보.** recurrence 도 convolution 도 없으므로 위치가 사라진다. 그래서 입력 embedding
에 sinusoid positional encoding 을 더한다 — 차원 2i 는 sin(pos/10000^(2i/d_model)), 2i+1
은 cos (§3.5, p.6). 학습된 embedding 과 결과가 거의 같았으나 (Table 3 (E), p.9) 학습 때
못 본 길이로 외삽할 가능성 때문에 sinusoid 를 택했다 (§3.5, p.6).

**왜 self-attention 인가.** 저자의 근거는 Table 1 (p.6) 세 축이다 — 층당 복잡도
O(n²·d) 는 n < d 일 때 recurrent 의 O(n·d²) 보다 작고, 순차 연산이 O(1) 이라 병렬화되며,
임의 두 위치 사이 경로 길이가 O(1) 이라 장거리 의존을 배우기 쉽다 (§4, p.6-7).
```

예시에서 볼 것 — `√dk` 의 이유, multi-head 의 이유, sinusoid 의 이유가 모두 **저자가 밝힌
것**으로 앵커와 함께 있다. 하이퍼파라미터는 메커니즘 이해에 필요한 것(h, dk, d_model)만
있고 Adam 의 β 값 같은 것은 없다 — 그건 재현하려는 사람이 논문에서 볼 것이다. 용어는
전부 영어다.

## 4. 논문 유형별 추출 항목

유형과 무관하게 이 아홉 가지는 찾는다. 없으면 **없다는 사실이 결과다** — `미보고`.

| 항목 | 대개 어디에 | 노트의 어느 절로 |
|---|---|---|
| 문제 설정 | §1 첫 두 문단 | 문제 |
| 기존 방법의 부족한 점 | §1 끝 · §2 | 문제 |
| 제안·검증 대상 | 초록 · §3 | 핵심 아이디어 |
| 데이터 (이름 · 규모 · 분할) | 실험 설정 절 | 실험이 보인 것 |
| 베이스라인 | 결과 표의 행 이름 | 실험이 보인 것 |
| 지표 | 결과 표의 열 이름 | 실험이 보인 것 |
| 계산 자원 | 실험 설정 · 부록 | 실험이 보인 것 |
| 핵심 수치 | 표. **산문 아님** | 실험이 보인 것 |
| ablation | 결과 절 후반 표 | 실험이 보인 것 |

**제안형 — 새 방법·모델·구조.** 기여는 "이것이 되게 만들었다". **제안한 것과 성능을 낸
것이 같은지** 확인한다. 방법은 A 인데 성능은 A+B+C 고 ablation 이 없으면 A 의 기여는
논문이 보이지 않은 것이다. 제안 요소를 낱개로 적고 각각이 ablation 표에 있는지 대조한다.

**분석·실증형 — 기존 것의 성질 규명.** 기여는 **주장과 증거**. 핵심 아이디어 절은 실험
설계로 채운다 — 무엇을 통제하고 무엇을 변화시켰나. 주장 문장을 원문 그대로 뽑고, 증거가
상관인지 개입인지 가른다. 상관을 인과로 옮겨 적지 않는다.

**데이터셋·벤치마크.** 기여는 자원. 수집·주석·검증 절차가 본체. 규모 · 도메인 · 출처 ·
라이선스 · 주석자 수와 일치도(κ, α) · 분할 방식과 누수 방지. 일치도 미보고는 중요한 결함이다.

**서베이.** 기여는 **분류 체계**. 문헌 수집 범위(기간 · DB · 포함/배제 기준)와 분류 축,
저자가 지목한 미해결 문제 목록. 수록 논문의 최신 연도가 2년 넘었으면 적는다.

**이론·증명.** 가정을 빠짐없이 — 가정이 곧 적용 범위다. 정리 진술은 원문 그대로 인용하고
풀어 쓰기는 그 아래. 실험이 있으면 검증이지 근거가 아니다.

**시스템.** 처리량 · 지연 · 비용을 **어떤 부하에서** 쟀나. 부하 조건 없는 수치는 쓸 수 없다.
비교 시스템의 버전·튜닝 여부.

## 5. 의심할 자리

여기서 걸린 것은 `읽으며 든 의문` 에 앵커와 함께 적는다. 걸리지 않았다고 적을 필요는
없다 — 노트는 심사 보고서가 아니다.

- **베이스라인 수치의 출처.** 직접 돌렸나, 다른 논문에서 가져왔나. 가져왔으면 설정이 같나.
- **튜닝 예산의 비대칭.** 제안 방법만 탐색을 많이 했으면 차이의 일부는 탐색량이다.
- **분산 없는 단일 값.** 시드 하나로 낸 0.3 차이는 차이가 아닐 수 있다.
- **평가셋 선택.** 여러 벤치마크 중 일부만 보고했으면 나머지는 어디 갔나.
- **지표와 주장의 불일치.** "자연스럽다" 는 주장을 정확도로 재고 있지 않나.
- **데이터 누수.** 사전학습 코퍼스에 평가 세트가 들어 있을 가능성을 다루는가.
- **인간 평가의 규모.** 평가자 수 · 문항 수 · 일치도가 없으면 수치를 그대로 옮기지 않는다.
- **상대 개선률만 보고.** "30% 향상" 뒤의 절대값이 0.4 → 0.52 일 수 있다.
- **그림의 y 축.** 잘려 있으면 차이가 커 보인다. 표에서 다시 확인.
- **원문 내부의 불일치.** 표와 본문의 값이 다른 경우가 실제로 있다(1706.03762 의 EN-FR
  BLEU 는 Table 2 가 41.8, §6.1 이 41.0). 감추지 말고 양쪽을 적는다.

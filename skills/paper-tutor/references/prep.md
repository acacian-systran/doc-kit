# prep — 사전지식 용어집

논문을 읽기 전에 알아야 할 용어를 **읽는 순서대로** 정리한다. 사전이 아니다 — 사전은
찾아보는 것이고 이것은 처음부터 끝까지 읽고 논문으로 넘어가는 것이다.

## 1. 어떤 용어를 뽑나

논문에 실제로 등장하는 용어만. 두 부류로 가른다.

| 부류 | 정의 | 어떻게 알아보나 |
|---|---|---|
| **prerequisite** | 논문이 정의하지 않고 독자가 안다고 가정하는 것 | 처음 나올 때 설명 없이 쓰이거나 참조 번호만 붙는다(`layer normalization [1]`) |
| **introduced** | 논문이 새로 정의하거나 자기 식으로 쓰는 것 | `We call our ...`, `we propose`, 따옴표, 그림 제목에 등장 |

**prerequisite 가 본체다.** 논문이 설명해 주지 않는 것을 여기서 설명한다. introduced 는
논문 본문이 설명하므로 한 줄과 정의 절 앵커만 적는다 — 독자가 논문에서 그 자리를 찾아
읽게 하는 것이 목적이다.

**개수는 10~20개.** 넘치면 자르는 기준은 "이걸 모르면 논문의 핵심 주장을 따라갈 수 없나".
하이퍼파라미터 이름(`warmup_steps`)이나 데이터셋 이름(`WMT 2014`)은 대개 용어집이 아니라
노트의 몫이다. 단 `BLEU` 처럼 결과를 읽는 데 필요한 지표는 넣는다.

**사용자 배경 반영.** "ML 은 알고 NLP 는 처음" 이면 `softmax`·`dropout` 은 빼고
`BLEU`·`byte-pair encoding` 은 넣는다. 배경을 말하지 않았으면 다 넣는다.

## 2. 순서

**의존 순서.** 뒤 용어의 설명이 앞 용어를 써도 되게 배열한다. `softmax` 가 `attention`
앞에, `attention` 이 `multi-head attention` 앞에. prerequisite 를 먼저 다 놓고 introduced 를
뒤에 놓으면 대체로 이 순서가 된다.

두 용어가 서로를 전제하면 더 일반적인 것을 앞에 둔다.

## 3. 항목 형식

```markdown
### <영어 표제어>  (<prerequisite|introduced> · <앵커>)
- 쉬운 설명: <비유·일상어. 1~2문장. 수식 없음. 중학생이 읽어도 그림이 그려져야 한다>
- 일반 설명: <해당 분야 학부 교재 수준. 2~3문장. 필요하면 수식 하나>
- 논문에서: <이 논문이 어디서 어떻게 쓰나. 일반 용법과 다르면 그 차이> (<앵커>)
- 한국어: <정착 번역어. 없으면 `없음 — 원어 사용`>
- 점검: <이 용어를 안다면 답할 수 있어야 하는 질문 하나>
```

**표제어는 영어 원문.** 검색·후속 독서가 모두 원어로 이뤄진다. `한국어` 줄은 있으면
적고 없으면 없다고 적는다. 억지로 만들지 않는다.

**`쉬운 설명`·`일반 설명` 은 논문 밖 일반 지식이다.** 앵커를 요구하지 않는다. 대신
논문의 용법과 충돌하면 안 된다 — 일반적으로 X 를 뜻하는데 이 논문은 Y 로 쓰면
`논문에서` 줄에 그 차이를 적는다.

**`점검` 줄은 quiz 모드의 문제 씨앗이다.** "정의를 말하라" 가 아니라 이 용어를 이해한
사람만 답할 수 있는 질문으로. 답이 `일반 설명` 안에 있어야 한다.

## 4. 머리말

```markdown
# <원제> — 읽기 전 용어집

읽은 범위: <본문 1-11쪽>
대상: <사용자가 말한 배경, 없으면 `배경 미지정 — 전체 수준`>
개수: prerequisite <n> · introduced <m>
```

## 5. 채운 예시 (Attention Is All You Need, 1706.03762)

20개 중 6개만 보인다. prerequisite 4개 → introduced 2개로 의존 순서가 잡힌 것을 본다.

```markdown
### sequence transduction  (prerequisite · §1, p.2)
- 쉬운 설명: 한 줄의 기호를 다른 줄의 기호로 바꾸는 일. 영어 문장을 독일어 문장으로,
  문장을 문법 트리로.
- 일반 설명: 가변 길이 입력 시퀀스를 가변 길이 출력 시퀀스로 사상하는 과제 군. 기계번역,
  음성인식, 구문분석이 여기 든다. 입력과 출력의 길이가 다를 수 있다는 점이 분류와 다르다.
- 논문에서: 논문이 다루는 과제 범위 자체다. "dominant sequence transduction models are
  based on complex recurrent or convolutional neural networks" (Abstract, p.1). 기계번역이
  주 실험이고 constituency parsing 이 일반화 실험이다 (§6.3, p.9).
- 한국어: 없음 — 원어 사용. (`시퀀스 변환` 을 쓰는 글도 있으나 정착되지 않았다)
- 점검: 감정 분류는 sequence transduction 인가? 아니라면 무엇이 다른가?

### softmax  (prerequisite · §3.2.1, p.4)
- 쉬운 설명: 여러 개의 점수를 "합이 1인 비율" 로 바꾸는 장치. 점수 차이가 크면 큰 쪽에
  거의 다 몰아 준다.
- 일반 설명: 벡터 z 를 exp(z_i)/Σ exp(z_j) 로 정규화해 확률 분포로 만든다. 입력 값이
  커질수록 분포가 한 점에 집중되고, 그 영역에서 gradient 가 매우 작아진다.
- 논문에서: attention 가중치를 만드는 자리 (Eq. 1, p.4). 입력이 커져 gradient 가 죽는
  성질이 곧 √dk 로 나누는 이유다 — "pushing the softmax function into regions where it
  has extremely small gradients" (§3.2.1, p.4).
- 한국어: 소프트맥스 (음역).
- 점검: 입력 벡터의 값을 모두 10배 하면 softmax 출력은 어떻게 달라지는가?

### residual connection  (prerequisite · §3.1, p.3)
- 쉬운 설명: 어떤 처리를 거친 결과에 처리 전의 입력을 그대로 더해 준다. 처리가 망쳐도
  원본은 남는다.
- 일반 설명: 서브층 f 에 대해 출력을 x + f(x) 로 만든다. f 가 항등함수에서의 차이만
  배우면 되므로 깊은 망에서 gradient 가 잘 흐른다. He et al. 2016 의 ResNet 이 출처다.
- 논문에서: 인코더·디코더의 모든 서브층을 `LayerNorm(x + Sublayer(x))` 로 감싼다 (§3.1,
  p.3). 이 덧셈이 가능하도록 모든 서브층 출력 차원을 d_model = 512 로 맞췄다 (§3.1, p.3).
- 한국어: 잔차 연결.
- 점검: 서브층 출력 차원이 입력과 달라도 residual connection 을 그대로 쓸 수 있는가?

### BLEU  (prerequisite · Table 2, p.8)
- 쉬운 설명: 기계가 낸 번역이 사람 번역과 단어 묶음이 얼마나 겹치는지 세어 0~100 으로
  낸 점수.
- 일반 설명: 후보 번역의 n-gram(보통 1~4) 이 참조 번역에 나타나는 정밀도를 기하평균하고,
  짧은 번역에 brevity penalty 를 준다. 구현(토큰화·대소문자 처리)에 따라 1점 안팎이 갈린다.
- 논문에서: 주 지표. Table 2 의 EN-DE 28.4, EN-FR 41.8 (p.8). 단일 값만 보고되고 분산은
  없다.
- 한국어: 없음 — 원어(약어) 사용.
- 점검: 두 논문의 BLEU 를 직접 비교하려면 무엇이 같아야 하는가?

### scaled dot-product attention  (introduced · §3.2.1, p.4)
- 논문이 정의한다. query 와 key 의 dot product 를 √dk 로 나눠 softmax 한 가중치로 value 를
  합한다 (Eq. 1, p.4). 나누는 이유는 §3.2.1 과 각주 4 (p.4).
- 점검: 나누지 않으면 dk 가 클 때 무슨 일이 생기는가?

### multi-head attention  (introduced · §3.2.2, p.4-5)
- 논문이 정의한다. Q·K·V 를 h 개의 다른 선형 사상으로 보내 attention 을 병렬로 h 번 하고
  이어 붙인다. h = 8, dk = dv = 64 (§3.2.2, p.5).
- 점검: head 를 8개로 늘리면 계산량은 단일 head 의 몇 배가 되는가? (힌트: dk 가 어떻게 바뀌나)
```

예시에서 볼 것 — `softmax` 항목의 `논문에서` 줄이 다음 항목 `scaled dot-product
attention` 의 핵심 이유를 미리 놓는다. 이것이 의존 순서다. `BLEU` 의 `점검` 은 정의를
묻지 않고 비교 조건을 묻는다 — 이 용어를 이해한 사람만 답할 수 있다.

## 6. 자주 하는 실수

- **알파벳 순.** 사전이 된다.
- **논문에 없는 용어.** "관련 있으니" 넣는다. 표제어를 `grep -i` 로 확인한다.
- **introduced 를 길게 설명.** 논문이 할 일을 대신하면 독자가 논문을 안 읽는다.
- **한국어 번역어를 표제어로.** `주의 기제` 로는 논문도 후속 논문도 검색되지 않는다.
- **점검 줄이 정의 확인.** "softmax 란?" 은 점검이 아니다.

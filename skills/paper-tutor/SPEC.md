# paper-tutor 스펙 (v0.2)

논문 한 편을 **공부하는** 스킬. 읽기 전 용어집, 읽는 중 Q&A, 읽은 뒤 노트와 퀴즈까지
네 모드를 한 스킬로 다룬다. `paper-review` 를 흡수한다 — 그 스킬의 앵커 규약과
추출기는 공통 규약으로 들어오고, 노트 형식은 학습자용으로 다시 짠다.

상태: 구현 완료(2026-09-18). 동작의 기준은 `SKILL.md` 와 `references/` 이고, 이 문서는 설계 근거 기록이다.

---

## 1. 한 문장 정의

논문을 받아 (prep) 읽기 전에 알아야 할 용어집, (ask) 읽는 중 원문 앵커로 답하는 Q&A,
(read) 읽은 뒤 메커니즘 중심의 노트, (quiz) 이해를 확인하는 대화형 퀴즈를 제공한다.
네 모드 모두 **원문에 있는 것만 말하고, 없는 것은 없다고 말한다.**

## 2. 형태

**스킬 하나, 모드 넷.** 서브에이전트가 아닌 이유 — 퀴즈와 Q&A 는 사용자와 한 턴씩
주고받는 대화이고, 서브에이전트는 격리 컨텍스트라 그 대화를 할 수 없다. 세션을 넘어
이어지는 상태(용어집·오답 기록·질문 로그)는 파일로 남긴다.

`paper-review` 는 이 스킬이 대체한다. 디렉터리를 지우고 `pdftext.py` 는 이쪽으로 옮긴다.
README 의 표와 설치 안내도 맞춘다.

## 4. 네 모드

### 4.1 `prep` — 사전지식 용어집

**언제.** 읽기 전. "이 논문 읽으려면 뭘 알아야 해", "용어 정리해 줘".

**무엇을 뽑나.** 논문에 실제로 등장하는 용어를 두 부류로 **갈라서**.

| 부류 | 정의 | 예 (Transformer) |
|---|---|---|
| prerequisite | 논문이 정의하지 않고 독자가 안다고 가정하는 것 | `sequence transduction`, `BLEU`, `softmax`, `residual connection` |
| introduced | 논문이 새로 정의하거나 자기 식으로 쓰는 것 | `scaled dot-product attention`, `multi-head attention`, `positional encoding` |

prerequisite 가 본체다. introduced 는 논문이 설명해 주므로 한 줄과 정의 절 앵커만.

**개수.** 10~20개. 넘칠 때 자르는 기준: "이걸 모르면 핵심 주장을 따라갈 수 없나".

**순서.** 의존 순서. 뒤 용어 설명이 앞 용어를 써도 되게(`softmax` → `attention`).
알파벳 순 금지 — 사전이 아니라 읽기 순서다.

**항목 형식.**

```markdown
### scaled dot-product attention  (introduced · §3.2.1, p.4)
- 쉬운 설명: <비유·일상어. 1~2문장. 수식 없음>
- 일반 설명: <학부 교재 수준. 2~3문장. 필요하면 수식 하나>
- 논문에서: <이 논문이 어디서 어떻게 쓰나. 일반 용법과 다르면 그 차이> (§3.2.1, p.4)
- 한국어: <정착 번역어. 없으면 `없음 — 원어 사용`>
- 점검: <이 용어를 안다면 답할 수 있어야 하는 질문 하나>
```

`쉬운 설명`·`일반 설명` 은 논문 밖 일반 지식이라 앵커를 요구하지 않는다. 대신 논문의
용법과 충돌하면 `논문에서` 항목에 적는다. `점검` 줄은 quiz 모드의 문제 씨앗이다.

**산출.** `glossary.md`

### 4.2 `ask` — 논문 기반 Q&A

**언제.** 읽는 중 언제든. "여기서 X 가 무슨 뜻", "저자들은 Y 를 어떻게 처리했어".

**답변 규약.**

- 근거 절·표·쪽을 앵커로. 원문 인용은 영어 그대로 따옴표에.
- **논문에 없으면 "논문에 없다" 를 먼저.** 일반 지식으로 보충할 때는 `논문 밖:` 접두.
- 논문이 모호하면 모호하다고 말한다. 저자가 안 한 결정을 대신 내리지 않는다.
- glossary 에 있는 용어면 그 항목을 가리킨다.

**산출.** `qa.md` — 질문·답·앵커·날짜 누적.

### 4.3 `read` — 노트

**언제.** 논문을 읽은 뒤, 또는 "이 논문 정리해 줘 / 요약해 줘".

**골격.** 심사자의 노트가 아니라 학습자의 노트다. 핵심 아이디어 절이 본체이고 분량
제한이 없다. 나머지 절은 3~5문장.

| 절 | 무엇을 | 분량 |
|---|---|---|
| 요지 | 이 논문이 주장하는 것 하나 | 1문장 |
| 서지 | 저자·출처·연도·링크·코드·읽은 범위 | 표 |
| 문제 | 무슨 문제이고 기존 방법은 왜 안 되나 | 3~5문장 |
| **핵심 아이디어** | 메커니즘을 그림·수식을 따라가며 설명. 입력이 어떻게 출력이 되나. 수식은 원문 번호로 인용(`Eq. 1`) | 제한 없음 |
| 실험이 보인 것 | 표에서 온 수치와 앵커만. 비교 조건이 다르면 같은 문장 안에 | 3~5문장 |
| 저자의 주장 | 측정이 아닌 해석·기여·시사점 | 3~5문장 |
| 한계 | **저자가 밝힌 것** / **읽으며 든 의문** 으로 나눠서 | 각 2~4문장 |
| 다음 | 이 논문 뒤에 읽을 것(논문이 인용한 것 중), 어디에 인용하나 | 2~3줄 |
| 키워드 | 논문에 실제로 나온 용어 5개, 영어 | — |

**읽는 순서.** 초록 → 결론 → 그림과 표 → 방법 → 서론. 서론은 저자의 프레이밍이라 마지막.
수치는 산문이 아니라 표에서.

**읽은 범위.** 본문 15쪽 초과·부록 절반이면 본문만 읽고 서지에 `읽은 범위` 를 적는다.

**논문 유형별 추출 항목**(제안형·분석형·데이터셋·서베이·이론·시스템)과 **의심할 자리**
체크리스트는 `references/read.md` 에 둔다. 본문에서는 참조만.

**산출.** `note.md`

### 4.4 `quiz` — 이해 확인

**언제.** 읽은 뒤. "퀴즈 내 봐", "내가 제대로 이해했나".

**문제 유형.** 셋을 섞는다. 사실만 내면 암기 시험이 된다.

| 유형 | 묻는 것 |
|---|---|
| 사실 | 무엇을 했고 무엇을 얻었나 |
| 이유 | 왜 그렇게 설계했나, 저자의 근거는 |
| 적용·비판 | 조건이 바뀌면, 저자가 보이지 않은 것은 |

**모든 문제에 정답과 앵커.** 원문으로 확인할 수 없는 문제는 내지 않는다.
glossary 의 `점검` 줄과 note 의 `읽으며 든 의문` 이 문제 씨앗이다.

**진행.** 한 문제씩.

1. 채점 — 맞음 / 부분 / 틀림. 부분은 무엇이 빠졌는지.
2. 틀리면 **정답 대신 힌트** — 다시 볼 절·표를 앵커로.
3. 두 번째도 틀리면 정답·해설·앵커.
4. 끝나면 오답이 몰린 개념을 짚고 glossary 의 어느 항목으로 돌아갈지 알린다.

기본 5문제. 수·난이도(입문/표준/심화) 지정 가능. `quiz.md` 에 기록이 있으면
"전에 틀린 것부터" 를 제안한다.

**산출.** `quiz.md` — 문제·정답·해설·앵커 + 회차별 채점 결과·날짜.

## 5. 공통 규약

- **앵커 없는 논문 주장을 쓰지 않는다.** `(Table 2, p.8)` · `(§3.2)`. 달 수 없으면 내가 만든 문장이다.
- **논문에 없으면 없다고 쓴다.** `미보고` 가 추정치보다 낫다. 추정은 `추정:` 접두.
- **측정과 주장을 가른다.** 결과 절에는 측정만.
- **수치를 다시 반올림하지 않는다.**
- **고유명사를 지어내지 않는다.** `grep -i '<이름>' paper.txt` 로 확인.
- **용어는 영어 원문.** 표제어·본문·질문·답 모두. 정착 번역어는 첫 등장에 괄호 병기.
- **따옴표 안은 원문 그대로.**
- 문체는 `korean-report-style`. 파일은 -다체, 퀴즈·Q&A 의 대화 자체는 대화체.

## 6. 원문 확보

`assets/pdftext.py` (paper-review 에서 이동). 규칙은 그대로 —
`--info` 로 진단, 기본 추출은 산문용, 표 있는 쪽만 `--layout`, 그림·수식·스캔본은
Read 로 PDF 직접. arXiv 는 `/pdf/` 또는 HTML 판. 붙여넣은 텍스트는 절 제목 앵커.

`paper.txt` 가 이미 있으면 다시 뽑지 않는다.

## 7. 파일 배치

```
notes/papers/<citekey>/          # citekey = 제1저자성-연도-제목첫단어
  paper.pdf                      # 있으면
  paper.txt                      # pdftext.py 출력, [[p.N]] 앵커
  glossary.md                    # prep
  qa.md                          # ask
  note.md                        # read
  quiz.md                        # quiz
```

사용자가 경로를 지정하지 않으면 이 규칙으로 쓰고 경로를 알린다. 묻지 않는다.

## 8. 모드 선택

사용자가 모드를 말하지 않으면 요청 문장으로 고른다.

| 요청 | 모드 |
|---|---|
| 뭘 알아야 해 · 용어 · 사전지식 · 배경 | prep |
| 여기서 ~가 뭐야 · 저자들이 ~는 어떻게 · 이 표가 무슨 뜻 | ask |
| 정리 · 요약 · 읽어줘 · 노트 | read |
| 퀴즈 · 확인 · 테스트 · 내가 이해했나 | quiz |
| 논문만 던지고 아무 말 없음 | 뭘 할지 한 줄로 묻는다 — 이건 물어야 한다. 네 모드가 다른 산출이다 |

권장 흐름(강제 아님): prep → 읽기(+ask) → read → quiz → 오답 → glossary 재독.

# 어휘 · 배치 · 문구

그림 한 장이 같은 어휘를 쓰면 라벨을 읽기 전에 구조가 보인다. 아래 표는 고정이다 — 새 뜻이 필요하면 역할을 늘리지 말고
먼저 기존 역할에 들어가는지 본다.

## 1. 타일 색 = 역할

| role | 범례(기본) | 뜻 | 흑백에서 |
|---|---|---|---|
| `in` | Input | 처리 밖에서 들어오는 것(스키마 · 문서 · 큐) | 흰 바탕 점선 테두리 |
| `rule` | Rule-based | LLM 없이 코드 규칙으로 하는 단계(변환 · 순회 · 검증 · 프롬프트 조립) | 흰 바탕 실선 |
| `search` | Retrieval | 색인에서 찾아 오는 단계 | 흰 바탕 실선 |
| `llm` | LLM | 모델을 부르는 단계 — **LLM이 닿는 곳이 한눈에 보이게 하는 것이 이 색의 일** | **회색 바탕**(흑백에서 유일한 채움) |
| `merge` | Integrate | 누적 상태에 쓰는 단계 · 누적 상태 자체(띠) | 흰 바탕 실선 |
| `out` | Output | 반복이 끝난 뒤 나오는 것 | 흰 바탕 실선 |
| `frag` | Fragment | 단계 사이를 오가는 중간 산출물(초안 · delta) | 흰 바탕 실선 |

범례 이름은 `legend.roles` 로 바꾼다(`{"merge": "Integrate"}`). 범례에서 빼려면 `legend.hide`.
흑백판은 논문용이다. LLM 단계만 회색으로 채우는 것은 본 논문 그림 규칙(회색 하나 = LLM이 닿는 단계)과 같다.

`assets/icons.svg` 에 있다. 32×32, 선 2, 둥근 끝. 타일 안 아이콘은 색판에서 흰색, 흑백판에서 잉크색.

| `rule` | 표 → 점 | 규칙 변환(direct mapping 등) |
| `filter` | 깔때기 | 분류 · 거르기 |

| `user` | 사람 | 사람 판정 · 사용자 |

같은 그림 안에서 같은 아이콘을 다른 뜻으로 쓰지 않는다.

## 3. 선 · 틀 · 글자 원

| 것 | spec | 뜻 |
|---|---|---|
| 실선 화살표 | `kind: flow` | 처리 순서 |
| 굵은 주황 화살표 | `kind: write` | 누적 상태에 씀. 라벨은 주황 굵은 글자(`hlt`) |
| 회색 점선 화살표 | `kind: read` | 읽기 · 실패 때 대체 경로 |
| 굵은 실선 | `loop: true` | 반복으로 돌아가는 선(다음 table · 다음 ticket) |
| 회색 점선 틀 | `frames[].kind: loop` | 반복 범위. 왼쪽 위 안쪽에 고정폭 글자로 `Iterate · <순서 기준>` |
| 파란 실선 틀 | `frames[].kind: group` | 같은 입력을 나란히 받는 형제 단계 묶음(검색 셋). 왼쪽 아래 안쪽에 `top-k` 같은 공통 설정 |
| 띠 | `kind: band` | 반복 내내 쌓이는 상태(core ontology · log). 두 줄 사이 가운데 |
| 마름모 | `kind: decision` | 반복 끝 판단 하나. 다른 분기는 그리지 않고 retry 선으로 |
| 글자 원 | `badge` | 실행 순서 a, b, c … 타일 왼쪽 위 모서리. 단계 목록 · 행렬 열과 같은 글자 |

## 4. 배치 규칙

사용자와 정한 것(그림 A 코드 기준판, 12번 고쳐 굳힘)이다. 새 그림도 이것부터 따른다.

1. **반복하는 단계만 고리에 넣는다.** 고리는 시계방향 사각형 — 윗줄 → 오른쪽 아래로 → 아랫줄 ← → 왼쪽 위로.
   반복 밖의 단계(입력 준비 · 마지막 검증 · 출력)는 고리에 넣지 않는다.
2. **바깥 연결은 한두 방향으로 모은다.** 입력은 모두 위, 출력은 모두 아래. 네 방향에 흩으면 읽기 어렵다.
3. **세로로 늘리지 않는다.** 줄은 고리 두 줄 + 입력 한 줄 + 출력 한 줄. 단계가 많으면 칸 간격(110)을 줄이거나 그림을 나눈다.
4. **누적 상태는 두 줄 사이 가운데 띠.** 쓰는 단계에서 띠로 굵은 주황(`write`), 띠에서 읽는 단계로 점선(`read`).
5. **판단은 아랫줄 왼쪽 끝.** no 는 왼쪽 변을 타고 위로(고리선), yes 는 바로 아래 출력 줄로. 왼쪽 변에는 고리선 하나만.
6. **retry · 실패 선은 아랫줄 밑 가로선.** 판정 · 검증 타일 아래에서 내려와 한 가로선으로 모여 생성 타일로 올라간다.
   라벨은 그 가로선 밑에 `reject / invalid → retry (k ≤ 3)` 처럼 조건 → 결과 한 줄.
7. **형제 단계는 틀로 묶고 틀 바깥에서 한 번만 들어가고 나온다.** 틀 안 타일마다 화살표를 따로 긋지 않는다.
8. 화살표는 직각만. 대각선 금지. 선이 타일 · 글자를 가로지르면 `check.py --render` 가 실패로 잡는다.

좌표 기준(viewBox 1000 폭):

| 것 | 값 |
|---|---|
| 타일 | 60×60, 모서리 8 |
| 같은 줄 타일 간격 | 중심 사이 110 (틀 안 형제는 90) |
| 입력 줄 · 윗줄 · 아랫줄 · 출력 줄 y | 40 · 170 · 440 · 600 (아랫줄 ↔ 윗줄 사이 270 안에 띠) |
| 띠 | 높이 52, 두 줄 가운데 (y 300 언저리) |
| 반복 틀 | 고리 바깥 10–40 여유, 고리선(x 134)이 틀 안쪽 |
| 범례 | 오른쪽 위 (x 700, y 46), 역할 3열 + 선 한 줄. 반복 틀 위쪽 변보다 위에서 끝나게 |

## 5. 문구

- **타일 제목은 영문, 첫 글자 대문자**(`Each table`, `Gen-LLM`, `Core ontology`). 설명 줄은 타일에 달지 않는다 — 설명은 tip 과 단계 목록에.
- 제목은 프로젝트 용어표의 용어 그대로. 같은 것을 그림 · 단계 목록 · 행렬 머리에서 다르게 부르지 않는다.
- 두 줄 제목은 `label: ["External", "ontology"]`. 위 · 아래 · 오른쪽 · 왼쪽 중 선이 없는 쪽에 둔다(`pos`).
- 선 라벨은 짧게: `approve`, `pass`, `yes`, `no`, `next table (i + 1)`. 서술 대신 `→`, `≤`, `·`.
- 사용자가 단계 문구를 직접 썼으면(md 파일 등) **글자 그대로** 옮긴다. 다듬자고 하지 않는다.
- 페이지 본문(lede · 보충 · 다른 점)은 korean-report-style. 덱에 들어갈 문구면 명사구로 끝낸다.

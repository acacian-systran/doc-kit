# 코드에서 그림으로

이 스킬의 그림은 "코드 기준판"이다 — 기억 · 논문 · 이전 그림이 아니라 **지금 코드가 도는 순서**를 그린다.
처음 만든 계기가 그것이었다: 아이콘판 그림이 DM(direct mapping)을 Prompt로만 보내고 있었는데,
코드를 읽어 보니 DM은 검색보다 먼저 누적 상태에 합쳐지고 있었다. 이전 그림 · 기억과 코드가 다른 곳을 찾는 것이 이 그림의 일이다.

## 1. 흐름 따라 읽기

1. **진입 함수 하나를 정한다**(`run()`, `main()`). 그림 한 장 = 함수 하나의 한 번 실행. 사용자에게 어느 함수인지 확인한다.
2. 그 함수를 위에서 아래로 읽으며 **실제 실행 순서**로 단계 표를 만든다. 칸: 글자 · 코드 위치(`file:line`) · 하는 일 · 읽는 것 · 쓰는 것 · 실패하면.
   - 반복문이 고리다. 반복문 밖에서 한 번 도는 것은 입력 줄 · 출력 줄로.
   - 상태에 쓰는 줄(`merge`, `append`, `save`, `+=`)을 모두 찾는다 — 띠로 가는 `write` 선이 된다. 몇 번 쓰는지 센다.
   - 상태를 읽는 줄은 `read` 선. 쓰기보다 앞인지 뒤인지 적는다(검색이 이번 반복의 결과를 보나?).
   - retry 루프의 횟수 상수, 빈 응답 · 파싱 실패 같은 예외 경로, 다 실패했을 때 남는 것.
   - 멈추는 곳(`raise`, `sys.exit`)과 retry 하는 곳을 구별한다.
3. 주석 · docstring 이 말하는 것과 코드가 하는 것이 다르면 코드를 따르고 보충에 적는다.
4. 같은 진입점에서 옵션으로 갈리는 방법(`--no-llm`, baseline)이 있으면 단계마다 쓰는지 표로 — `matrix`.

LLM 프롬프트 · 응답을 보려고 실행하지 않는다. 코드만 읽어 순서를 정한다. 실행 로그가 이미 있으면 순서 확인에 쓴다.

## 2. 무엇을 어디에 적나

| 자리 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 타일 제목 | 용어표의 단계 이름 | 설명, 함수 이름 |
| tip(마우스 · Tab) | `(c) 함수명(인자)`: 하는 일 한두 문장, 읽고 쓰는 것, 위치 | 추측 |
| 단계 목록 `steps` | 글자마다 한 줄. 사용자가 쓴 문구가 있으면 그대로 | 코드 위치 |
| 보충 `notes` | 단계 문구에 안 들어가는 코드 동작(입력 범위 · retry 횟수 · 실패 경로), `ref` 에 `file:line` | 다른 점 비교 |
| 행렬 `matrix` | 방법 × 단계: ● 그대로 · ◐ 일부(tip 으로 어떻게) · 빈칸 | 성능 수치 |
| 다른 점 `diff` | 이전 그림 · 기억 · 논문 그림과 코드가 다른 곳, 한 행에 하나 | 고칠 제안 |
| 확인 결과 `verdict` | 사용자가 "맞나 확인"을 물었을 때 그 답 한 줄 + 근거 | 묻지 않은 판정 |

## 3. 감추지 않기

- 문제 있는 경로(3번 실패하면 버려짐, 실패하면 run 멈춤)는 그림에서 빼지 않는다. 점선 · 라벨로 그대로 그리고 보충에 적는다.
  복잡해서 뺐으면 캡션에 "그림에서 뺌"이라고 쓴다.
- tip 에 쓴 코드 위치는 그림을 만든 시점의 것이다. 페이지 머리 또는 보충 lede 에 기준 커밋을 적는다.

## 4. 외부에 내는 그림

- 투고 · 외부 덱용이면 코드 경로 · 파일명이 그림 안(타일 · 라벨)에 들어가지 않게 한다 — tip 과 보충에만. PNG 로 뽑으면 tip 은 사라진다.
- 덱용은 색판 PNG, 논문용은 흑백판 PNG(`export.py --mode bw`). 논문 본문에 넣을 최종본은 프로젝트 규칙(draw.io · 손그림 등)을 따르고,
  이 페이지는 그 밑그림 · 코드 대조 기준으로 쓴다.

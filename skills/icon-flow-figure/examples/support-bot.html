답변 봇 처리 흐름

가상의 고객 문의 답변 봇 support_bot.py의 run()이 도는 순서대로 그린 그림. 타일에 마우스를 올리거나 Tab으로 옮기면 그 단계가 코드에서 하는 일이 나옴. 코드 · 수치는 모두 가상.

확인 결과: Reply log 검색은 이번 ticket의 답변을 보지 못함.

(i) Save reply가 (d) 검색보다 뒤에 있으므로, (d)는 앞 ticket까지 저장된 답변만 찾음. 첫 ticket에서는 (d) 결과가 비어 있음.

그림 1 · 코드 기준

ticket 하나마다: 분류 → 검색 → 초안 · 검토 · 정책 검사 → 저장

(h)가 두 번 더 실패하면 그 ticket은 저장하지 않고 사람 상담원 큐로 넘김(그림에서 뺌, 보충 참고).

처리 단계 (a)–(k)

  1. aTickets를 접수 시각 순서로 하나씩 처리
  2. b키워드 규칙으로 billing · bug · other 분류
  3. cFAQ docs에서 제목 + 분류로 상위 5개 검색
  4. dReply log에서 같은 분류의 지난 답변 상위 5개 검색
  5. eticket 본문 · 분류 · (c)(d) 결과를 묶어 Prompt 생성
  6. fLLM이 Prompt를 받아 답변 초안 생성
  7. gLLM이 초안을 ok · fix · reject로 판정. reject면 지적을 붙여 retry
  8. h금지어 · 환불 금액 상한 규칙 검사. 실패 시 이유를 붙여 retry
  9. i통과한 답변을 Reply log에 저장
  10. j마지막 ticket이면 (k)로. 아니면 (a)로 돌아가 다음 ticket
  11. k분류별 처리 수 · 재시도 수를 Daily report로 집계

# 추출 항목

논문에서 뽑을 것은 유형마다 다르다. 제안형 논문의 틀로 서베이를 읽으면 "이 논문의
방법은 무엇인가"라는 답 없는 질문에 매달리다 요약이 헐거워진다.

## 1. 공통

유형과 무관하게 이 아홉 가지는 찾는다. 찾다가 없으면 **없다는 사실이 결과다** — 노트에
`미보고` 로 적는다.

| 항목 | 대개 어디에 | 노트의 어느 절로 |
|---|---|---|
| 문제 설정 | §1 서론 첫 두 문단 | 연구 목적 |
| 기존 방법의 부족한 점 | §1 끝 · §2 관련 연구 | 연구 목적 |
| 제안·검증 대상 | 초록 · §3 | 연구 방법 |
| 데이터 (이름 · 규모 · 분할) | §5 실험 설정 | 연구 방법 |
| 베이스라인 (무엇과 비교) | 결과 표의 행 이름 | 연구 방법 · 주요 결과 |
| 지표 (무엇으로 쟀나) | 결과 표의 열 이름 | 연구 방법 |
| 계산 자원 (하드웨어 · 시간 · FLOPs) | §5 · 부록 | 연구 방법 |
| 핵심 수치 | 표. **산문 아님** | 주요 결과 |
| 제거 실험(ablation) | 결과 절 후반 표 | 주요 결과 |

## 2. 유형별

### 제안형 — 새 방법·모델·구조

기여는 "이것이 되게 만들었다"이다. **제안한 것과 성능을 낸 것이 같은지** 확인한다.
방법은 A 를 제안했는데 성능은 A+B+C 를 합쳐 냈고 ablation 이 없으면, A 의 기여는
논문이 보이지 않은 것이다. 그 사실을 `읽으며 든 의문` 에 적는다.

- 제안 요소를 낱개로 적는다(구조 변경 · 학습 목표 · 데이터 처리 · 추론 기법).
- 각 요소가 ablation 표에 있는지 대조한다.
- 하이퍼파라미터 탐색을 제안 방법과 베이스라인에 같은 예산으로 했는지 본다.

### 분석·실증형 — 기존 것의 성질을 규명

기여는 방법이 아니라 **주장과 그 증거**다. 노트의 `연구 방법` 절은 실험 설계로 채운다 —
무엇을 통제하였고 무엇을 변화시켰나.

- 주장 문장을 원문에서 그대로 뽑아 둔다. 저자의 표현이 곧 주장의 범위다.
- 증거가 상관인지 개입인지 가른다. 상관을 인과로 옮겨 요약하지 않는다.
- 반례·예외를 저자가 어디까지 인정하는지 본다.

### 데이터셋·벤치마크 논문

기여는 자원이다. 성능 수치는 부수적이고, **수집·주석·검증 절차**가 본체다.

- 규모 · 언어/도메인 · 수집 출처 · 라이선스.
- 주석자 수 · 자격 · 지침 · 일치도(κ, α). 일치도 미보고는 중요한 결함이다.
- 분할 방식과 누수 방지(같은 출처 문서가 train/test 에 갈라져 있나).
- 베이스라인 점수는 난이도의 지표로만 읽는다.

### 서베이·리뷰

기여는 **분류 체계**다. 노트의 `연구 방법` 절에는 문헌 수집 범위(기간 · 데이터베이스 ·
포함/배제 기준)를, `주요 결과` 절에는 분류 축과 각 축의 갈래를 적는다.

- 분류 축이 몇 개이고 서로 직교하는지.
- 저자가 지목한 미해결 문제 목록 — 이것이 서베이에서 가장 인용 가치가 높다.
- 수록 논문의 최신 연도. 2년이 지났으면 노트에 적는다.

### 이론·증명

- 가정을 빠짐없이 옮긴다. 가정이 곧 적용 범위다.
- 정리의 진술을 원문 그대로 인용하고, 번역은 그 아래 풀어 쓴다.
- 실험이 있으면 그것은 검증이지 근거가 아니다. 결과 절에서 구분한다.

### 시스템·엔지니어링

- 처리량 · 지연 · 비용을 어떤 부하에서 쟀나. 부하 조건 없는 성능 수치는 쓸 수 없다.
- 비교 대상 시스템의 설정(버전 · 튜닝 여부)이 공정한가.
- 운영 기간과 규모. 벤치마크와 실사용 데이터를 가른다.

## 3. 재현성 신호

서지 표의 `코드` 칸을 채울 때 같이 확인한다. 있으면 노트에, 없으면 `없음` 이라고 적는다.
`없음` 이 빈칸보다 정보가 많다.

- 코드 공개 주소 · 라이선스
- 학습된 가중치 공개 여부
- 데이터 공개 여부, 비공개면 그 이유
- 하이퍼파라미터 전체(부록 포함) 명시
- 랜덤 시드 · 반복 횟수 · 분산
- 평가 스크립트(BLEU 구현 차이만으로 1점이 갈린다)

## 4. 결과를 옮기기 전에 의심할 자리

여기서 걸린 것은 `읽으며 든 의문` 절에 앵커와 함께 적는다. 걸리지 않았다고 적을 필요는
없다 — 노트는 심사 보고서가 아니다.

- **베이스라인 수치의 출처.** 저자가 직접 돌린 것인가, 다른 논문에서 가져온 것인가.
  가져온 것이면 설정이 같은지 논문이 밝히고 있나.
- **튜닝 예산의 비대칭.** 제안 방법만 탐색을 많이 했으면 차이의 일부는 탐색량이다.
- **분산 없는 단일 값.** 시드 하나로 낸 0.3 차이는 차이가 아닐 수 있다.
- **평가셋 선택.** 여러 벤치마크 중 일부만 보고했으면 나머지는 어디 갔나.
- **지표와 주장의 불일치.** "자연스럽다"는 주장을 정확도로 재고 있지 않나.
- **데이터 누수.** 사전학습 코퍼스에 평가 세트가 들어 있을 가능성을 논문이 다루는가.
- **인간 평가의 규모.** 평가자 수 · 문항 수 · 일치도가 없으면 수치를 그대로 옮기지 않는다.
- **상대 개선률만 보고.** "30% 향상" 뒤의 절대값이 0.4 → 0.52 일 수 있다. 절대값을 찾는다.
- **그림의 y 축.** 축이 잘려 있으면 차이가 실제보다 커 보인다. 수치는 표에서 다시 확인한다.
- **원문 내부의 불일치.** 표와 본문의 값이 다른 경우가 실제로 있다. 발견하면 감추지 말고
  결과 절에 양쪽을 적는다.

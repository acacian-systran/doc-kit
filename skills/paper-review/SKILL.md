# 논문 리뷰 요약

논문을 읽고 학술지 리뷰 형식의 한국어 노트로 만든다. 규칙은 하나로 요약된다 —
**원문 앵커가 없는 문장은 노트에 넣지 않는다.** 요약이 원문보다 확신에 차는 것이
이 작업의 유일한 실패 방식이고, 그 확신은 대개 앵커를 달 수 없는 문장에서 나온다.

자재는 이 스킬 디렉터리에 있다.

| 파일 | 무엇 |
|---|---|
| `assets/pdftext.py` | PDF → 쪽 앵커(`[[p.N]]`)가 붙은 텍스트 |
| `references/template.md` | 노트 템플릿, 채운 예시, 비교표 템플릿 |
| `references/extraction.md` | 논문 유형별 추출 항목, 재현성 신호, 결과를 의심할 자리 |

---

## 1. 시작 전 결정

**무엇을 만드나.**

| 요청 | 산출 | 분량 |
|---|---|---|
| 논문 한 편 요약 | 노트 1개 | A4 1~2쪽 |
| 여러 편 | 노트 n개 + 비교표 1개 | 노트마다 위와 같음 |
| "이거 인용할 만해?" | 노트 없이 대화로 답한다 | 3~5문장 |

세 번째를 노트로 만들지 않는다. 판단을 물었는데 요약이 오면 답이 어디 있는지 다시
찾아야 한다.

**어디에 두나.** 사용자가 지정하지 않으면 `notes/papers/<citekey>.md`,
citekey 는 `제1저자성-연도-제목첫단어`(`vaswani-2017-attention`). 물어보지 말고 이
규칙으로 쓰고 경로를 알린다.

**어디까지 읽나.** 본문 15쪽이 넘고 부록이 절반이면 본문만 읽는다. 대신 노트에
`읽은 범위: 본문 1-9쪽, 부록 미독`을 적는다. 읽지 않은 것을 읽은 척하지 않는다.

## 2. 원문 확보

### 2.1 PDF 파일

```bash
python3 <스킬경로>/assets/pdftext.py paper.pdf --info            # 먼저 진단
python3 <스킬경로>/assets/pdftext.py paper.pdf                   # paper.txt
python3 <스킬경로>/assets/pdftext.py paper.pdf --pages 8 --layout # paper.p8.layout.txt
```

쪽마다 `[[p.N]]` 이 붙는다. 노트의 앵커는 여기서 가져온다 — 눈대중으로 쪽 번호를
적으면 검증할 수 없는 앵커가 되어 없느니만 못하다.

**표가 있는 쪽만 `--layout` 을 붙여 따로 뽑는다.** 기본 추출은 열을 무너뜨린다.
실제로 Transformer 논문 Table 2 를 기본값으로 뽑으면 모델 이름 10개가 먼저 나오고
BLEU 값 8개와 9개가 뒤이어 나온다 — 어느 값이 어느 모델의 것인지 복원할 수 없는데,
읽으면 복원한 것 같은 착각이 든다. 반대로 2단 조판 산문에 `--layout` 을 쓰면 좌우 단이
한 줄에 붙어 서로 다른 두 문장이 하나로 합쳐진다. 그래서 산문은 기본값, 표 쪽만
`--layout` 이다.

**그림·수식·스캔본은 Read 로 PDF 를 직접 본다.** `pdftotext` 는 그림 안의 글자를 읽지
못하고 수식을 문자 나열로 뭉갠다. Read 의 `pages` 인자로 쪽을 지정한다(요청당 20쪽).
`--info` 가 "글자가 거의 없는 쪽"으로 지목한 쪽이 대개 그 대상이다.

### 2.2 arXiv

`arxiv.org/abs/<id>` 가 아니라 `arxiv.org/pdf/<id>` 를 받는다. abs 는 초록 페이지라
본문이 없다. HTML 판(`arxiv.org/abs/<id>v<n>` 의 HTML 링크나 ar5iv)이 있으면 그쪽이
표와 수식이 온전해 PDF 보다 낫다.

### 2.3 붙여넣은 텍스트

쪽 번호가 없으므로 앵커를 절 제목으로 단다(`§3.2 Method`). 없는 쪽 번호를 지어내지
않는다. 절 번호도 없으면 노트 머리에 `앵커: 절 단위 불가(원문 일부만 제공됨)` 를 적는다.

### 2.4 인용 시 주의

`pdftotext` 는 줄바꿈 하이픈을 붙여 `left-toright`, `pretraining` 같은 말을 만든다.
원문 그대로 따옴표에 넣을 문장은 PDF 를 눈으로 한 번 확인한다.

## 3. 읽는 순서

초록 → 결론 → 그림과 표 → 방법 → 서론. 서론을 마지막에 두는 이유는 서론이 저자의
프레이밍이어서, 먼저 읽으면 결과를 저자가 보라는 대로 보게 되기 때문이다.

**수치는 본문 산문이 아니라 표에서 가져온다.** 산문의 수치는 반올림되어 있고
조건이 생략되어 있다.

무엇을 뽑을지는 논문 유형마다 다르다. **쓰기 전에 `references/extraction.md` 를 읽는다.**

## 4. 노트 작성

`references/template.md` 를 복사해 채운다. 골격은 이렇다.

| 절 | 무엇을 | 분량 |
|---|---|---|
| 요지 | 이 논문이 주장하는 것 하나 | 1문장 |
| 서지 | 저자·출처·연도·링크·코드·읽은 범위 | 표 |
| 연구 목적 | 무슨 문제이고, 왜 기존 방법으로 안 되나 | 3~5문장 |
| 연구 방법 | 무엇을 어떻게. 데이터셋·베이스라인·지표를 명시 | 3~5문장 |
| 주요 결과 | 수치와 그 출처 표 | 3~5문장 |
| 결론 | 저자가 주장하는 기여와 시사점 | 3~5문장 |
| 한계와 향후 연구 | 저자가 밝힌 것과 읽으며 든 의문을 **나눠서** | 각 2~4문장 |
| 키워드 | 논문에 실제로 나온 용어 5개 | — |
| 어디에 인용하나 | 어떤 맥락에서 이 논문을 끌어올 수 있나 | 2~3줄 |

절마다 3~5문장을 지킨다. 넘어가면 요약이 아니라 번역이고, 번역이 필요하면 요약 노트가
아니라 번역본을 만들어야 한다.

## 5. 정확도 규약

이 절이 스킬의 본체다.

- **앵커 없는 문장을 쓰지 않는다.** 수치와 주장 뒤에 `(Table 2, p.8)` · `(§3.2)` 를 단다.
  달 수 없으면 그 문장은 논문이 아니라 내가 만든 것이다.
- **논문에 없으면 없다고 쓴다.** `학습 시간 미보고` 가 빈칸이나 그럴듯한 추정치보다 낫다.
  추정을 꼭 적어야 하면 `추정:` 을 앞에 붙여 원문과 구분한다.
- **저자의 주장과 관측된 결과를 가른다.** "EN-DE BLEU 28.4 (Table 2)" 는 결과이고
  "구조가 단순해 병렬화가 쉽다" 는 주장이다. 노트에서 두 문장이 나란히 서면 독자는 둘 다
  측정된 것으로 읽는다. 결과 절에는 측정된 것만 넣고 주장은 결론 절로 보낸다.
- **수치를 다시 반올림하지 않는다.** 27.3 을 27 로 적는 순간 다른 논문과의 0.3 차이가
  사라지는데, 그 0.3 이 논문이 존재하는 이유인 경우가 많다.
- **비교 조건이 다르면 그 사실이 결과의 일부다.** 파라미터 수·학습 데이터·평가 세트가
  베이스라인과 다르면 결과 문장 안에 적는다. 따로 적으면 아무도 연결해 읽지 않는다.
- **용어는 첫 등장에서 원어를 병기한다** — `주의 기제(attention)`. 이후로는 정착된 한국어
  용어가 있으면 그것을, 없으면 원어를 그대로 쓴다. 억지 번역어는 검색을 막는다.
- **따옴표 안은 원문 그대로.** 번역했으면 따옴표를 떼고 `요지는 ~이다` 로 쓴다.

## 6. 여러 편을 함께 읽을 때

한 편씩 노트를 먼저 쓰고, 그다음에 비교표를 만든다. 비교표부터 만들면 표의 열에 맞는
것만 읽게 된다.

**표의 축은 논문이 아니라 질문으로 잡는다** — `무엇을 다르게 했나 / 무엇으로 쟀나 /
무엇을 못 했나`. 그리고 **논문마다 다른 지표를 한 열에 넣지 않는다.** 나란히 놓인 수는
비교 가능한 것으로 읽히므로, 한쪽이 BLEU 이고 한쪽이 COMET 이면 열을 나누거나 지표
이름을 셀마다 적는다. 템플릿은 `references/template.md` 후반에 있다.

## 7. 쓰고 나서 확인

- [ ] 앵커 없는 수치가 있나 — `grep -nE '[0-9]+([.,][0-9]+)?%?' note.md` 로 한 줄씩 훑는다
- [ ] 결과 절에 저자의 주장이 섞였나
- [ ] 한계 절이 `저자가 밝힌 것` / `읽으며 든 의문` 으로 갈렸나
- [ ] 논문에 없는 고유명사(데이터셋·모델·지표 이름)를 지어냈나 —
      `grep -i '<이름>' paper.txt` 로 원문에서 확인한다
- [ ] 키워드 5개가 모두 논문에 실제로 나오는 용어인가
- [ ] 읽지 않은 범위를 서지 표에 적었나

## 8. 다른 스킬과의 관계

- **문체** — `korean-report-style`. 노트도 보고 문서다. -다체, AI 문투 제거가 그대로 적용된다.
- **HTML·PDF 산출** — `korean-report-doc`. 노트를 배포용 문서로 만들 때만 부른다.
  노트 자체는 마크다운으로 남긴다 — 나중에 grep 해서 다시 찾을 것이기 때문이다.
- **구조 그림** — `d2-diagram`. 아키텍처를 그려야 이해되는 논문일 때.

# 브리프 — 그리기 전에 적는 것

Mermaid AI(mermaid.ai)의 생성 가이드는 프롬프트를 **다이어그램 유형 + 주제 + 핵심 요소**
세 조각으로 쓰라고 한다. "채용 프로세스 그림"이 아니라 "채용 프로세스 플로차트 — 단계는
서류 검토·전화 면접·기술 면접·최종 면접·오퍼, 각 단계에 탈락 경로"다. 이 스킬은 그
구조를 사람이 요청을 받았을 때도 그대로 쓴다 — 요청이 오면 먼저 아래 브리프를 채우고,
채워지지 않는 칸이 있으면 그것이 되묻는 질문이다.

브리프는 그림 파일 머리말(`%% 답하는 질문:` · `%% 상태:` · `%% 읽는 법:`)과 그림
디렉터리 README 의 표에 그대로 들어간다. 따로 보관하지 않는다.

## 브리프 서식

```
유형      : flowchart | container | sequence | state | er | gantt | mindmap
답하는 질문: <한 문장. 두 문장이면 그림이 둘>
상태      : To-Be(목표 구조) | As-Is(현재 상태, 갱신 의무 있음) | 파생(시점 박고 쓰고 버림)
주제      : <무엇의 그림인가 — 시스템 · 모듈 · 한 요청 · 한 대상 · 저장소 · 일정>
핵심 요소 :
  - 단계/참여자/상태/엔터티 (5~12개. 넘으면 나눈다)
  - 축 — 이것만 따라가면 전체가 읽히는 선
  - 조건 · 게이트 — 어디서 대상이 줄어드나
  - 저장소 — 무엇이 어디에 남나 (DB · 파일 · 색인)
  - 비결정 — LLM · 외부 판정이 닿는 곳
  - 미확정 — 설계가 아직 정하지 않은 자리 (구현 안 됨과 다르다)
근거 문서 : <spec 파일명 §절 · 회의록 · PRD>  ← 그림에 그리지 않고 주석에 적는 것
```

## 유형 고르기

| 질문이 이렇게 생겼으면 | 유형 | 템플릿 |
|---|---|---|
| 무엇이 어떤 순서로 무엇을 남기나 | flowchart | `_template-flow.mmd` |
| 경계가 어디고 무엇이 같이 죽나 (상자 20+ · 배포 경계 여럿) | flowchart + 중첩 subgraph + elk | `_template-container.mmd` |
| 한 요청이 누구를 어떤 순서로 부르나 | sequenceDiagram | `_template-sequence.mmd` |
| 한 대상이 어떤 상태를 거치나 | stateDiagram-v2 | `_template-state.mmd` |
| 무엇이 무엇을 몇 개 갖나 | erDiagram | `_template-er.mmd` |
| 무엇이 언제 돌고 무엇을 기다리나 | gantt | `_template-gantt.mmd` |
| 한 주제 아래 무엇이 갈라지나 (구조 없는 나열) | mindmap | 템플릿 없음 — 문법은 grammar.md |

**"한 대상이 지나가는 순서"와 "한 실행이 도는 순서"가 다르면 그림이 둘이다.** 앞은
flowchart 또는 state, 뒤는 sequence. 비동기 대기(제출과 회수 사이 24시간)가 끼면
반드시 갈라진다.

## 요청을 브리프로 옮기는 예

> "우리 파이프라인 아키텍처 그려줘"

채워지는 것이 없다. 되묻는다 — 답하는 질문(단계인가 경계인가), 상태(To-Be 인가),
근거 문서. 그림 하나에 셋 다 담으려는 요청이면 셋으로 나눠 제안한다.

> "수집 → 필터 → LLM 판정 → 저장, cron 이 돌린다. 필터 조건은 score ≥ 0.8. 저장은
> Postgres 와 out/ 디렉터리. LLM 벤더는 아직 미정"

```
유형      : flowchart
답하는 질문: 문서 한 건이 수집에서 저장까지 어느 단계를 지나고 무엇을 남기나
상태      : To-Be
핵심 요소 : 트리거 cron · 단계 4 (수집·필터·판정·저장) · 게이트 score ≥ 0.8 (filter)
            · 저장소 Postgres(table) + out/(file) · 비결정 LLM 판정 · 미확정 벤더(tbd)
```

이대로 `_template-flow.mmd` 를 채운다.

## 정제 요청 — 그린 뒤에 오는 말

Mermaid AI 문서가 나열한 정제 요청은 사람이 받을 때도 같은 종류다. 어느 쪽으로 갈지
미리 정해 둔다.

| 요청 | 하는 일 |
|---|---|
| 상자 더하기 · 빼기 | 노드 한 줄 + 선 한 줄. 팔레트 클래스를 잊지 않는다 |
| 방향 바꾸기 | `flowchart TD` ↔ `LR`. 세로가 길어지면 LR — 단, 한 줄에 상자 7개 넘으면 다시 TD |
| 유형 바꾸기 | 브리프로 돌아간다. 질문이 바뀐 것이다 |
| 묶기 | `subgraph`. 점선 = 논리 그룹, 실선 = 배포 경계 (style 로) |
| 단순화 | 상자를 지우는 게 아니라 **질문을 좁힌다**. 지운 것은 다른 그림에 있어야 한다 |
| 색 바꾸기 | 그림 파일이 아니라 `_palette.mmd` 를 고치고 `sync_palette.py` 로 뿌린다 |
| 오류 고치기 | mermaid.ai 의 "Fix with AI" 대신 `render.sh` 의 파서 오류 줄 번호를 읽는다. 함정 목록은 grammar.md 끝 |

## 원본 문서가 있을 때

Mermaid AI 는 PDF·Word·회의록을 올려 그림을 뽑는다. 사람이 할 때도 같다 — 근거
문서를 먼저 읽고 브리프의 "핵심 요소"를 그 문서의 절 번호와 함께 채운다. 문서에
없는 상자는 `tbd`(미확정) 다. 문서에 없는 것을 그려 넣고 그림이 근거가 되는 순환을
막는 장치다.

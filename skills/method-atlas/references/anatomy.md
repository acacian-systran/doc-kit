# 페이지 해부 — 각 부분이 답하는 질문과 쓰는 법

기준 예시: `examples/text2sparql.data.js` (T1–T10). 아래 예문은 모두 거기서 왔다.

## 머리

| 요소 | 키 | 쓰는 법 |
|---|---|---|
| 제목 | `title` · `h1` | 「<문제 영역> 기법 비교」. `h1` 에 범위 `(T1–T10)` 를 붙여도 된다 |
| 한 줄 설명 | `lede` | 무엇을(근거 이름들) 어떤 기준으로 비교하는지 + 필터 규칙 한 문장 |
| 공통 예시 질문 | `question` | 모든 기법이 따라가는 입력 하나 |
| 색 범례 | `legend` | 핵심 색 2개 — 사전 구축 자원(`idx`), 원천 데이터 직접 접근(`kg`) |

## 보기 스위치 · 흐름 지도

- 머리 오른쪽 「보기」 단추: 흐름 지도 · 조합 · 간략 상세. 보는 사람이 켜고 끈다(브라우저에만 저장).
- **흐름 지도**(`map`) — 「어느 문제를 어디서 누가 막나」 를 한 장에. 행은 문제를 쪼갠 축(막는 실패 · 조회 대상), 열은 핵심 축(개입 시점).
  기법에 올리면 그 기법 한계의 「→ Tn」(맡는 쪽, 주황)과 이 기법을 「→」 로 가리키는 쪽(점선)이 강조되고, 아래 줄에 한계 문장이 나온다.
  빈 칸은 「그 지점에서 그 문제를 막는 기법이 없다」 는 뜻이라 사용자에게 빈칸을 짚어 줄 근거가 된다.

## 필터 보드

- 구조 분류 | 운영 요건 두 묶음. 칩 옆 숫자는 「이 칩을 더 누르면 남을 개수」(다른 축 조건 반영).
- `criterion`: 핵심 축의 판정 기준을 문장으로. 경계 사례 하나를 예로 든다 (「T10 은 SAGA 에서 Mid, 단발 생성 뒤 재시도 루프에서 Post」).

## 기법 카드 목록

`id` 배지 · `short` · `one`(한 줄, 선택 시 펼침) · 「비교」 체크. 필터에 걸리지 않은 카드는 흐려질 뿐 사라지지 않는다.

## 상세 탭 — 위에서 아래로 「무엇 → 어떻게 → 실제 값 → 실제 예 → 득실 → 위치 → 이웃」

### ① 머리
- 메타 줄: id(개입 시점 색) · 개입 시점 값들 · 필터 미해당 배지.
- 배지 줄: 근거(● 핵심 · ○ 부분 사용, 누르면 근거 탭 카드로) + `badges`(예: 조회 방식, 검색 증강).
- `one` 한 문장, 그 아래 원문 정의 블록: 원문 영어 용어를 살린 정의 + 식(`formula`) + 출처 절(`§3.1.2`) + 원본 링크.

### ② 작동 방식 — 구조도
C4 component 도식. 격자(열 `c` 0–4, 행 `r` 0–2)에 노드를 놓는다.

| 노드 `k` | 모양 · 색 | 쓰는 곳 |
|---|---|---|
| `tech` | 개입 시점 색, 굵은 테두리 | 이 기법 자체 (하나) |
| `llm` | 진한 테두리 | LLM · controller |
| `store` | 원통, `idx` 색 | 미리 만든 인덱스 · 메모리 |
| `kg` | 원통, `kg` 색 | 원천 데이터 · endpoint |
| `io` | 둥근 회색 | 입력 · 중간 산출 · 출력 · refusal |
| `other` | 점선, `ref` 로 이동 | 이 흐름에 끼는 다른 기법 |
| `build` | 기본 | 구축 단계(생성 · 임베딩 · 학습) |

- 행 0 = 사전 구축(`off:true`, 점선 경계 「배포 시 1회 구축」), 행 1 = 질의 시점 주 흐름(왼쪽 질문 → 오른쪽 출력), 행 2 = 질의 시점에 부르는 원천 · 분기(refusal 등).
- 질의 시점 간선에는 번호 `n` 을 1부터 붙이고, `steps[n-1]` 에 그 간선에서 일어나는 일을 **공통 예시의 실제 값**으로 쓴다.
- 조회는 `both:1`(양방향), 되먹임 루프는 `route:"above"|"below"`.
- 노드 설명 `d` 는 2줄 이하, 줄당 한글 12자 안팎. 넘으면 상자를 넘친다.
- 끝에 `offNote`(사전 구축 한 줄: 무엇을 만들고, 무엇이 바뀌면 다시 만드나) 또는 `offNone`(구축 없음 이유).

### ③ 단계별 입출력 (접힘)
가로 3~5칸, 각 칸 = 라벨(`l`) + 상자. 검색형 기법의 기본 칸: **검색 키 → 처리 방식 → 출처 → 조회 결과 → 반영 위치**.
변환형(분해 · 출력 형식 변경)은 **입력 → 처리 → 출력 → 전달 대상 → 반영 위치**.
상자 안: `t` 원문 용어, `v` 실제 값(한국어), `m` 코드 · 트리플(고정폭), `s` 보충(수치 · 조건), `tag` 이 값을 준 다른 기법, `c` 색(`idx` · `kg`).

### ④ 예시 (접힘)
1. 예시 데이터(`ex.data`) — 이 기법을 설명하는 데 필요한 트리플만. 함정 데이터(잘못 입력된 edge, 동명 개체)를 일부러 넣는다.
2. 소단계 `<h4>① …</h4>` 2~4개 — 기법이 실제로 하는 일을 순서대로, 중간 산출을 표 · `<pre>` 로.
3. **결과 비교표** `| | LLM 이 쓴 쿼리 | 결과 |` — 「Tn 없음」 1~2행(실패 모양이 다른 것), 「Tn 있음」, 가능하면 「Tn 있음, 오선택」.
4. `<h4>쓰지 않으면</h4>` · `<h4>막지 못하는 것</h4>` · `<h4>오히려 해가 되는 경우</h4>` 중 해당하는 것.
5. 근거 수치가 있으면 마지막에 작은 표 (「SAGA 수치 (모델, 데이터셋) | 값」).

예시 HTML 에 쓸 수 있는 요소: `h4`, `p`, `pre`, `code`, `.tw>table`, `p.src`(회색 주석), `.tt`(tooltip).

### ⑤ 장단점 · 한계
2×2 — 행: 사용 · 미사용, 열: 장점 · 단점. 「미사용의 장점」 칸을 비우지 않는다(비용 · 단순성 · 오탐 없음 등).
`limit` 은 「무엇을 한다. 무엇은 못 한다 (→ Tn).」 두 문장.

### ⑥ 분류 · 운영 요건
축마다 이 기법의 칩 + `notes[축 key]` 설명. `badges` 의 세 번째 값(설명)이 있으면 구조 묶음 끝에 행으로 붙는다.
`notes` 기호: ● 필요 · 큼, ○ 부분 · 선택, — 없음.

### ⑦ 연관 기법
여섯 줄(있는 것만): 선행 · 후속 · 보완 · 대체 · 충돌 · 자원 공유. 각 칩에 짧은 이유(`why`)를 달 수 있다.

## 비교 탭
체크한 기법(기본 `compareDefault`)을 열로. 행 순서: 요약 → 구조 축 → 근거 → 배지 → 운영 설명 → 한계.
모든 값이 같은 행 이름 옆에 「· 같음」 — 표시가 없는 행을 읽으면 차이만 보인다.
기본 비교 묶음은 **같은 문제를 다른 시점에 푸는 기법들**(T4 Entity Linking · T8 Identifier Grounding처럼 대체 관계)이 좋다.

## 간략 상세
「간략 상세」 를 켜면 상세가 요약 · 구조도 · 장단점 · 한계만 펼친 채 시작하고, 단계 설명 · 입출력 · 예시 · 분류 · 연관 · 원문 정의는 접힌다.

## 조합 탭
실무에서 함께 쓰는 묶음 2~3개. 묶음마다 기법 칩 → 축 값별 ● 표(마지막 열 막힘 / 남음, 자동 계산) → 남는 위험 → 드는 것.
묶음은 「작게 시작 → 표준 → 다 갖춤」 처럼 비용 순으로 놓고, 남는 위험 문장은 표의 「남음」 과 맞춘다.

## 요약 행렬
모든 기법 × 구조 축(+ 배지, 근거). 필터 미해당은 흐리게. 행을 누르면 상세.

## 근거 탭
맨 위 비교표(근거 · 해결하려는 문제 첫 문장 · `sourceColumns` · 핵심 기법 ●), 그 아래 근거마다 카드:
해결하려는 문제 → 핵심 구조(「이름 — 설명」 목록) → 주장 → 쓰는 기법 칩 → 기법별 적용(접힘, 기법의 `bySource`) → 한계.

## 용어집
묶음 3~4개: 핵심 축의 용어 · 분류 용어 → 표 셀에 나오는 용어 → 영역 기본 용어. 행 = 용어 · 뜻(원문 영어 용어 유지) · 출처(절).
이 페이지가 정한 기준(판정 기준, 작명)은 출처 칸에 「Claude 제안 — 이유」 처럼 누구 판정인지 적는다.

# 분류 축과 관계 정하기

## 축을 고르는 순서

1. 기법을 다 나열하고, 두 기법씩 짝지어 「둘은 무엇이 다른가」 를 한 줄씩 적는다. 반복해서 나오는 차이가 축이 된다.
2. 차이를 두 묶음으로 나눈다.
   - **구조 분류** — 기법의 작동 자체: 무엇을 미리 만드나(사전 구축) · 어디서 가져오나(출처) · 무엇을 가져오나(조회 대상) · 어떻게 고르나(처리 방식) · 언제 끼어드나(개입 시점).
   - **운영 요건** — 도입 · 운영하는 사람이 묻는 것: 실행 구조(에이전트 · 고정 루프 · 단발), 사람 손이 드는 일(수작업 작성 · 데이터 품질 의존), 데이터가 바뀌면(즉시 반영 · 재인덱싱 · 수작업 수정), 근거.
3. 축마다 옵션 3~6개. 「없음」 이나 「영향 없음 · 미미」 를 둬서 모든 기법이 값을 갖게 한다. 한 기법이 둘 이상 가질 수 있다(`v:{stage:[0,1]}`).
4. 옵션 하나에 기법이 하나도 없거나 전부 몰리면 그 옵션 · 축은 변별력이 없으니 합치거나 뺀다.

## 핵심 축 (색)

엔진의 색 슬롯은 `pre` · `mid` · `post` 셋이고, 각 기법의 `stage` 가 그중 하나다(배지 · 구조도의 이 기법 상자 색).
보통 **개입 시점**(LLM 생성 호출 기준 전 · 중 · 후)을 쓴다. 다른 문제에서 더 맞는 3분할이 있으면 그것을 쓰되 키는 그대로 두고
`stages[i].short` 와 축 `opts` 이름만 바꾼다. 축 key 가 `stage` 가 아니면 `labels.stageAxis` 에 그 key 를 적는다.

판정 기준은 반드시 문장으로 `criterion` 에 쓴다. 기준이 모호하면 같은 기법을 사람마다 다르게 분류한다.
Text2SPARQL 의 기준: 「LLM 이 SPARQL 을 작성하는 호출 기준. Pre = prompt 구성, Mid = 호출 도중(에이전트 턴 사이의 observation, 출력 형식 변경), Post = 출력 쿼리의 검사 · 치환 · 실행」.

옵션 색(`cls`)은 `idx`(사전 구축 자원) · `kg`(원천 직접 접근) · `none`(점선, 「없음」) 만 쓴다. 색이 의미를 갖는 옵션에만 붙인다.

## 기호

| 기호 | 뜻 | 쓰는 곳 |
|---|---|---|
| ● | 핵심 · 예 · 필요 | 근거(`sources`), 배지, `notes` 첫 글자 |
| ○ | 부분 사용 · 원리상 가능 · 선택 | 같음 |
| — | 아니오 · 없음 | 같음 |
| ‡ | 원문에서 확인하지 않은 추론 | 문장 끝, 관계 `why` |
| * | 원문에 없는 작명 | 기법 · 옵션 이름 끝 |

## 관계 여섯 가지

`rel:[[종류, 대상 id, 이유?]]` — 한쪽에만 적는다.

| 종류 | 뜻 | 엔진이 하는 일 | 예 |
|---|---|---|---|
| 선행 | 이 기법이 돌려면 대상이 먼저 있어야 한다 | 대상 쪽에 「후속」 으로 보인다 | T6 ← T5 (lookup 결과를 거른다) |
| (후속) | 대상이 이 기법의 결과를 받는다 | 선행에서 자동 생성, 직접 쓰지 않는다 | |
| 보완 | 함께 쓰면 이득, 따로도 돈다 | 양쪽 | T9 · T10 (스키마 위반 / 빈 결과) |
| 대체 | 같은 문제를 다른 지점에서 푼다 | 양쪽 | T4 · T8 (생성 전 / 생성 후 IRI 접지) |
| 충돌 | 함께 쓰기 어렵다 | 양쪽 | T7 · T2 (예제도 placeholder 형식이어야 ‡) |
| 자원 공유 | 같은 사전 자원을 쓴다 | 양쪽 | T1 · T6 · T9 (스키마 인덱스) |

서로를 선행으로 적은 쌍(T7 ↔ T8)은 개입 시점이 앞선 쪽을 선행으로 두고 「함께 필요」 로 표시한다.
선행 · 후속에 이미 있는 대상은 보완에서 빠진다.

## 한계 → 다른 기법 화살표

한계 문장 끝의 `(→ Tn)` 은 관계 표와 별개로, 「이 기법이 남긴 문제를 누가 맡는가」 를 보여 준다.
모든 기법의 화살표를 이어 보면 기법들이 문제 a 의 어느 부분을 나눠 맡는지가 드러난다 — 만들고 나서 한 번 이어 보고,
아무도 맡지 않는 한계가 있으면 사용자에게 「이 빈칸을 맡는 기법을 더 찾을지」 묻는다.

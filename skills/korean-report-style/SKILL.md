# 한국어 문서 문체

파일로 남거나 다른 사람에게 보내는 한국어 문서의 문장 규약이다. 색·도해·HTML/PDF 제작은 범위 밖이다.

대화 답변, 발표 대본, 슬라이드의 읽는 노트, 코드 주석에는 적용하지 않는다. 말로 전하는 글은
말의 리듬이 맞다.

## 0. 우선순위

1. 사용자가 정한 문체·용어·높임
2. 고치는 문서에 이미 자리 잡은 문체와 용어
3. 이 규약

뜻을 지키는 것이 간결함과 구조보다 앞선다. 이 규약을 따르다 사실이 빠지거나 바뀌면 규약을 버린다.

## 1. 어체

- 문서 본문은 평서체(`~한다` · `~이다`)로 쓴다. 송부 메일·요청문은 합니다체로 따로 쓴다.
  한 문서에 두 체가 섞이면 초안처럼 읽힌다.
- `했다`와 `하였다`, `됐다`와 `되었다`는 모두 표준어다. 조직 관례나 기존 문서를 따르고,
  정한 것이 없으면 `했다`를 쓴다. 한 문서 안에서는 하나로 맞춘다.
- 인용·코드·로그는 원문 그대로 둔다.

## 2. 문장 — ASD-STE100에서 가져온 원칙

ASD-STE100은 비원어민 정비사가 정비 문서를 한 가지 뜻으로만 읽게 하려고 만든 통제 영어다.
아래 원칙은 한국어 보고 문서에도 그대로 통한다. 두 가지는 가져오지 않는다.

- **단어 수 상한**(절차 20단어, 서술 25단어). 한국어 어절은 영어 단어와 대응하지 않는다.
  길이 대신 한 문장에 주장이 몇 개인지 본다.
- **폐쇄 승인 어휘**(약 900단어). 한국어판이 없고, 만들어도 글을 쓸 때마다 대조할 수 없다.
  §2.4의 「한 용어 한 뜻」만 가져온다.

### 2.1 한 문장에 주장 하나

이유나 조건은 같은 문장에 둘 수 있다. 독립된 주장이 둘이면 문장을 나눈다.

> ✗ 재순위 모델을 교체해 nDCG@10이 0.412에서 0.447로 올랐고 지연도 늘었는데 캐시를 붙이면 해결될 것이다.
> ✓ 재순위 모델을 교체해 nDCG@10이 0.412에서 0.447로 올랐다. p95 지연은 180ms에서 210ms로 늘었다. 캐시 적용 후 다시 측정한다.

### 2.2 절차는 한 단계에 행동 하나

단계는 실행 동사로 끝낸다. 조건은 행동 앞에, 경고는 위험한 단계 앞에 둔다.

> ✗ 설정 파일을 열어 포트를 바꾸고 재시작하면 반영되니 운영 중에는 주의할 것.
> ✓ 운영 중인 서버라면 먼저 트래픽을 빼낸다.
>   1. `config.yaml`을 연다.
>   2. `port`를 `8080`으로 바꾼다.
>   3. 서비스를 재시작한다.

인수인계·재현 문서는 이미 끝난 작업과 독자가 할 단계를 나눈다. 끝난 작업은 과거형으로 기록하고,
독자가 실제로 실행할 단계만 명령형 번호 목록에 넣는다. 끝난 코드 작업까지 명령형으로 쓰면 독자가
다시 해야 하는지 확인만 하면 되는지 알 수 없다.

### 2.3 책임이 걸린 문장의 행위자

누가 하는지가 독자의 다음 행동을 정하면 피동으로 감추지 않는다. 원문에 행위자가 있으면 드러내고,
행위자가 중요하지 않은 상태 알림은 피동이어도 된다.

> ✗ 검토 후 반영될 예정이다.
> ✓ 데이터팀이 10월 24일까지 검토하고 반영한다.

원문에 행위자가 없으면 지어내지 않는다. `담당 미정`은 담당 배정이 실제 쟁점인 자리(미결 과제 표,
결정 요청)에만 쓴다. 담당 언급이 없는 문장마다 붙이면 원문에 없는 공백을 만든다.

### 2.4 한 용어는 한 뜻, 같은 대상은 같은 이름

문서 중간에 `평가셋` · `테스트셋` · `벤치`를 섞어 같은 것을 가리키지 않는다. 같은 말을 다른 뜻으로도
쓰지 않는다. 사업 문서나 계약서에 이미 정의된 말(예: 「양산」이 인증 이후를 뜻함)은 그 뜻을 따른다.
독자가 모를 약어는 처음 나올 때 풀어 쓴다.

### 2.5 비유·의인화·구어 환언 대신 대상과 동작

주어를 사람이나 물건으로 바꿔 넣어 자연스러우면 빌려 온 비유다. `세션이 살아 있다`,
`값이 튄다`, `큐가 밀린다`, `반토막이 난다`는 무엇이 어떻게 되었는지를 쓴다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 세션이 살아 있다 | 세션이 유지된다 |
| 값이 튄다 | 이상치가 나타난다 |
| prompt와 condition이 싸운다 | prompt와 condition이 상충한다 |
| 조용히 실패한다 | 오류 없이 실패한다 |
| 반토막이 된다 | 절반으로 줄어든다 |

개념의 이름은 비유가 아니므로 남긴다 — `드리프트`, `dead code`, `liveness probe`, `킬러 디펙트`.
이름은 남기고 서술만 고친다.

### 2.6 행동은 서술어로

`계측 신뢰도에 대한 정량화를 통한 제고`처럼 명사를 쌓으면 판단이 문장 끝으로 밀린다. 동사로 되돌린다.
`저장 실패` · `승인 여부`처럼 상태를 가리키는 짧은 명사형은 표와 제목에서 그대로 쓴다.

### 2.7 정확한 말의 선택

쉬운 말이 정확하면 쉬운 말을 쓴다. 쉬운 말이 해석을 여럿 남길 때만 그 자리에서 좁은 말을 쓴다.

판정법: 그 동사에 목적어를 바꿔 끼워 본다. 서로 다른 행위가 모두 성립하면 갈라 쓴다.
`넘긴다`는 데이터·업무·권한에 모두 붙으므로, 책임 범위가 걸린 문장에서는 `전달` · `이관` · `위임` 중
하나를 고른다. 걸린 것이 없으면 `넘긴다`로 충분하다.

한자어와 영문은 뜻을 좁힐 때만 쓴다. `상기` · `하기` · `익일` · `요망`은 뜻을 좁히지 않으므로
`위` · `아래` · `다음 날` · `요청한다`로 쓴다.

### 2.8 원문 표기 보존

식별자 · enum · 필드명 · 명령 · 경로 · 오류 메시지는 backtick으로 감싸고 철자를 바꾸지 않는다.
`SUCCESS`를 「성공」으로 옮기면 코드와 문서가 어긋난다. API에 같은 철자로 있는 말은 영문
(`payload`, `endpoint`)으로, 분야에 정착한 개념어는 음차(`드리프트`)로 쓴다.

## 3. 편집 시 뜻 보존

다듬기 · 완화 · 축약 · 목록화는 표현만 바꾸는 작업이다. 모델이 고친 문장에서 실제로 자주 바뀌는 것은
아래 항목이다. 고친 뒤 원문과 나란히 놓고 확인한다.

<!-- style-teaching -->
| 항목 | 바뀌기 쉬운 예 |
|---|---|
| 양태 | `할 수 있다`(가능) → `해야 한다`(의무), 권고 → 지시 |
| 부정 범위 | `모두 통과하지 못했다` — 전부 실패인지 일부 실패인지 |
| 수치·경계 | `이상` ↔ `초과`, `약 30%` → `30%`, %와 %p, 기준값 누락 |
| 확실성·출처 | 추정 → 확인, 전언 → 사실, `기록 없음` → `수행하지 않음` |
| 단계 | 요청 · 착수 · 진행 · 완료 · 중단 |
| 결정 상태 | `수정 대상이다`(미결) → `수정한다`(확정), 제안 → 결정 |
| 행위자·대상 | 누가 누구에게 무엇을 |

명료하게 만든다는 이유로 원문에 없는 원인 · 수치 · 담당자 · 일정을 보태지 않는다. 필요하면 사용자에게 묻는다.

## 4. 상태와 위험

### 4.1 결과를 먼저

상태 보고는 첫 문장에 질문의 답(완료 · 미완료 · 실패)과 수치를 둔다. 배경은 그 뒤에 온다.
개념 설명이나 학습 노트는 이해 순서를 따른다.

### 4.2 상태는 주장 옆에

추정을 실측처럼 쓰지 않는다. 범례에만 두지 말고 주장이 있는 자리에 붙인다.

| 표기 | 뜻 |
|---|---|
| 실측 | 실제로 측정한 값 |
| 구현됨 | 수단은 있으나 이 측정에는 쓰지 않음 |
| 미측정 | 아직 측정하지 않음 |

가운데 단계의 이름은 분야에 맞춘다(계측 문서라면 `레시피 보유`). 세 단계 구조는 유지한다.

### 4.3 미달과 위험 — 사실과 대응

제목의 주어를 결함에서 조치로 옮기는 것은 괜찮다. 기간 · 규모 · 원인은 지우지 않는다.

> ✗ 장비 매칭 검증 경로 복구
> ✓ 장비 매칭 검증 경로 복구 — 3일 중단 후 10월 14일 재개

대응이 아직 없으면 항목을 빼지 말고 `대응 미정`으로 남긴다.

### 4.4 기준 변경 고지

이전에 공유한 수치와 산출 기준이 달라졌으면, 수치가 좋아졌더라도 기준 변경을 수치 옆에 쓴다.

### 4.5 압박 없는 서술

소요와 위험은 사실로 쓴다. `하루면 끝난다`, `지금 시작하지 않으면 위험하다` 대신 선행조건과 착수 시점을 쓴다.
결정을 요청할 때는 우리 판단과 근거를 먼저 내놓고 조정을 청한다.

## 5. AI 문투

생성 모델이 쓴 한국어에 남는 고정 문형이다. 한 번 나온다고 틀린 것은 아니지만, 절마다 반복되면 내용 대신
리듬이 읽힌다.

<!-- style-teaching -->
| 문형 | 예 | 고치는 법 |
|---|---|---|
| 이항 대조 | `문제는 성능이 아니라 구조다` | 부정된 쪽을 지워도 뜻이 남으면 Y만 진술한다 |
| 도입 예고 | `결론부터 말하면` · `핵심은 이렇다` | 지우고 결론을 쓴다 |
| 봉합 접속 | `즉,` · `결국` · `다시 말해` | 앞 문장을 고쳐 한 번에 진술한다 |
| 맺음 훈계 | `개선이 필요할 것으로 보인다` · `향후 성과가 기대된다` | 담당 · 기한 · 결정 항목으로 바꾸거나 지운다 |
| 자기 설명 | `본 문서는 …을 위한 자료로, 각 절은 …을 담는다` | 문서가 할 말을 바로 쓴다 |
| 리듬 | 절마다 세 항목 병렬, 굵게 남발, 이모지 불릿 | 항목 수는 사실이 정한다. 굵게는 절당 한 곳 이하 |

줄표(—)는 제목 한정에 쓰는 표준 부호이므로 금지하지 않는다.

## 6. 제목은 명사구

서술형 제목은 논평처럼 읽히고 문서를 고치면 낡는다. 제목은 주제를 가리키고 주장은 본문이 한다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 일정이 말하는 것 | 일정 시사점 |
| CD는 같은 웨이퍼 안에서도 흔들린다 | 웨이퍼 내 CD 편차 |
| 캐시를 적용하는 방법 | 캐시 적용 |

한정이 필요하면 줄표를 쓴다 — `오버레이 — 핵심이자 약점`. 도해 안의 제목은 그림의 주장이므로 문장이어도 된다.

## 7. 편집 후 정합성

항목을 지우거나 넣으면 다른 곳이 어긋난다. 고칠 때마다 확인한다.

- [ ] 번호 — 절 · 그림 · 표 · 리스크(`S1~Sn`) 번호가 이어지는가
- [ ] 참조 — 「§5.1」, 「그림 8」이 실제 대상을 가리키는가
- [ ] 요약문 — 지운 항목을 언급하는 문장이 남아 있지 않은가
- [ ] 중복 — 같은 내용이 도해 라벨과 캡션, 두 절에 동시에 있지 않은가
- [ ] 미사용 정의 — 쓰이지 않게 된 도해 · 표가 남아 있지 않은가

연쇄를 발견하면 조용히 고치지 말고 알린다 — "S3을 지우면 요약문이 S4를 가리키는데 함께 고칠까요".

## 8. 내보내기 전 점검

### 8.1 표기 관례

- 작성자는 팀명보다 개인명 — `A사 · 홍길동`
- 파일명은 `YYMMDD_사업명_문서종류`
- 문서 끝에 인사말 · 회사명 · 로고를 붙이지 않는다

### 8.2 외부 공유

조직 밖으로 보내는 문서는 내부 문서를 다듬을 때 그대로 남기 쉬운 것을 확인한다.

- [ ] 비밀 — 비밀번호 · 토큰 · 접속 정보는 자리표시자로 바꾸고 바꿨다고 밝힌다
- [ ] 내부 경로 — 상대방이 열 수 없는 파일 경로 · 저장소 링크는 `(내부)`로 표시하거나 필요한 내용을 본문에 옮긴다
- [ ] 내부 식별자 — `D7` · `C1` 같은 내부 번호는 처음 나올 때 풀어 쓰거나 용어 표에 모은다
- [ ] 작업 흔적 — 세션 메모, 초안 표시, 내부 담당 메모가 남아 있지 않은가

풀어 쓸 때도 원문에 없는 정의를 추론해 넣지 않는다. 원문에서 뜻을 확인할 수 없으면 사용자에게 묻는다.

## 9. 검사기

```bash
python <스킬경로>/assets/lint.py 초안.md               # 줄·열과 제안을 낸다
python <스킬경로>/assets/lint.py 산출물.html           # HTML은 보이는 글자만 검사
python <스킬경로>/assets/lint.py 초안.md --heuristic   # 이항 대조·software 비유까지
python <스킬경로>/assets/lint.py 초안.md --format github  # CI annotation (sarif · json도 있음)
```

## 10. 사용자 확인 사항

- **한계 서술 삭제** — 임의 기준이나 미측정 항목을 지우면 수치가 검증된 것처럼 읽힌다. 한 줄로 옮겨 남길지 묻는다.
- **정정 고지** — 톤을 낮추더라도 이전 수치의 정정과 기준 변경은 남긴다.
- **조직 내부 용어** — 현장에 굳은 말(`골든 웨이퍼`, `핫 로트`)은 임의로 바꾸지 않는다.
- **삭제의 연쇄** — 한 항목을 지워 다른 항목이 무의미해지면 함께 정리할지 묻는다.
